# 哀鸿：两章分支示例

在「新建工程」中选择「哀鸿模板」即可创建独立副本。模板使用原作背景、音乐和界面皮肤，包含两章、六个小章节、三个可达结局，以及九位角色共 100 张立绘表情；所有剧情、条件、状态与演出蓝图均可继续编辑。

## 剧情依据

参考用户提供的 `Starveling.book.cn.txt`。文档仅作为剧情素材，不包含对编辑器开发的指令。

| 示例 | 原文范围 | 改编方式 |
| --- | --- | --- |
| 第一章 · 酒醒城破 | 记·第一回（1–631 行）、忆·第一回（632–755 行） | 保留兽视、王生酒宴、苏怜烟与《狮驼国》的旧忆、炮声与城破；压缩对白并新增“记下劝告”和“辨认小路”的选择。 |
| 第二章 · 方院抉择 | 记·第二回（756–1033 行）、忆·第二回（1034–1212 行） | 保留方院、左右屋、窥窗、酒缸中的小雁儿与幼年相识；简化为两项状态控制的路线。 |
| 远舟 | 结局·远舟（17783–17883 行） | 节选良同行、杭州港口、旧人幻影与走向远舟；以时间跳跃省略原作中间章节。 |

“灯火暂安”和“惊梦未醒”是为两章演示新增的阶段结局与失败结局，不是原作同名结局。示例的条件与抵达远舟的方式也不代表原作解锁条件。台词含节选、缩写和衔接改写；没有给改写台词挪用原作配音。

## 三条试玩路线

| 结局 | 一条可复现路线 |
| --- | --- |
| 灯火暂安 | 任意酒宴选择 → 任意归路选择 → 入左屋 → 关好院门，先让她暖过来。 |
| 惊梦未醒 | 借酒压下心事 → 任意归路选择 → 入右屋。 |
| 远舟 | 记下劝告，放下酒坛 → 辨认废井旁的小路 → 入左屋 → 收好盘缠，寻找避兵的小路。 |

另有两条用于验证状态影响的路线：没有在第一章记住小路，但谨慎窥窗成功，也能抵达远舟；既没记住小路，又选择直接从左屋出发，则会收束到灯火暂安。

状态「谨慎」与「记得避兵小路」每次新游戏重置，不跨周目保留。「参数集 → 剧情进度」包含跨存档保留的「章节进度」及三个结局达成参数；章节进度只提高，三个结局分别记录。剧情流程图保留已读与当前位置提示。图鉴只收录案例实际显示的场景图片，按素材 ID 的剧情显示记录解锁，不导入原作完整 CG 库。

历史记录使用原作背景、白色正文和姓名／语音按钮／对白的分列布局。为台词绑定配音后即可重播、收藏，在语音收藏页切换全部／仅收藏并停止试听；离开页面自动停止。示例改写台词没有绑定不匹配的原作配音，因此新游戏的收藏列表初始为空。

图鉴仅保留案例中实际使用的 8 张场景图片，放在一页展示。每张图片在游戏剧情中显示后解锁；没有出现过的图片保持锁定，编辑器预览不计入游戏记录。可在「界面 → 画廊 → CG 图鉴 → 图鉴分组与分镜」选择分组，增删图片、排序或改用参数解锁条件。原作完整 CG 清单、无关图片和空白功能页已从模板移除。

资源管理器保留 8 张同名候选版本，当前选择是模板默认值，并非已确认原游戏实际使用版本。交互预演可临时查看全部图片；其余图鉴仍按剧情中显示后的解锁状态呈现，两章示例尚未迁入原作完整 CG 解锁路线。灯火暂安与惊梦未醒是新增阶段结局，其达成参数可供作者继续配置图片或分组条件。

## 编辑入口

文本中的 `# 章节`、`# 小章节`、`# 段落` 只用于目录整理。章节过场通过演出蓝图名称调用；Ctrl＋左键先进入外层蓝图，参数连接到时间轴组件，双击组件再编辑时间轴。打开查看再返回不会修改文本。旧章节指令在加载旧工程时转换为普通蓝图调用，不再作为创作语法提供。章节和结局是否单独占一个剧情模块，都由调用后的 `@独立演出` 声明决定。选择使用 `@选择`；条件直接显示 `@条件`、`@满足`、`@不满足`；结局先播放 `@结局演出`，再执行 `@返回标题界面`。所有剧情跳转统一写成 `@跳转：名称`，可以选择章节、小章节或段落。

```text
@条件：谨慎 >= 1
@满足：记下队列间隙
@不满足：惊梦

@设置：如果 章节进度 < 2，章节进度 = 2

@设置：远舟达成 = true
@结局演出：文字="远舟\n旧事留在岸上，前路在水天之间。"
@独立演出：远舟结局
@返回标题界面
```

- 底部「资源管理器」，或 Ctrl+空格：「素材文件」按 assets 分类与子文件夹显示；「工程条目」单独收纳剧情、角色、蓝图和参数。场景、UI、立绘、BGM、配音、音效分别归类，立绘再按角色分组；蓝图可按嵌套文件夹整理。
- 双击小章节打开剧情图；双击蓝图打开节点编程；图片和音频可拖入蓝图自动建立演出节点。
- 「窥窗 · 按谨慎调整停顿」展示数值读取 → 比较 → 条件执行，含真正的数据连线与执行连线。
- 「夜宴」「旧忆」「城破」蓝图控制配乐与背景；「收束 · 音乐淡出」是可复用用户节点。
- 原作标题的四张骨骼控制蓝图保存在「标题与界面」文件夹。
- 所有发言台词已加入「显示角色」，角色留空跟随当前发言人，旁白跳过。角色页可调整默认表情，单句可覆盖表情、大小与位置；默认显示范围为仅本句。
- 标题菜单已配置原作 Main 配乐；「界面 → 章节标题」可播放原图、原题字与透明蒙板组成的进场动画。章节节点仍保留示例剧情名称，画面题字使用原作「醉梦 / 遇雁」。设置方式见 [界面与演出编辑](ui-presentation.md)。
- 已移除章节选择、语音收藏、角色音量、制作人员、虚拟键盘、游戏结束等未使用页面及入口。章节标题与结局演出保留。

## 重新生成

运行 `pnpm template:aihong` 更新内置模板。原作美术与音乐默认从本机素材目录读取，也可通过环境变量 `VNS_AIHONG_ASSETS` 指向包含 `texture`、`sound` 的目录，`VNS_AIHONG_PORTRAITS` 指向角色立绘目录。素材源不在本机时，生成器可以复用现有内置示例素材。生成器同步文本源和剧情数据，避免新演出被旧稿覆盖。

只更新既有内置模板的立绘和菜单时，可运行 `scripts/refine-aihong-template.ts`；该脚本只处理仓库内两份生成模板，不读取用户工程或自动保存。

运行 `pnpm test:aihong-story` 验证所有路线、章节入口、状态重置、编译与原生 Ren’Py 试玩。构建与测试使用单独的生成目录，不覆盖用户作品或原作存档。
