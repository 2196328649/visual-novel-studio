# 框选三个按钮后的等距分布

用户反馈：框选了三个按钮，等距按钮仍不可点击。

## 原因与修正

旧实现要求两端之间有足够空间，让所有控件之间的间距为非负；只要计算出负间距，就以“空间不足”禁用操作。这也会拦住轻微重叠、完全可以整理的按钮。框选完成后，画布与布局工具使用同一组选中 ID，本次未修改框选逻辑。

只读检查作者工程，右上角的“封面切换、设置、退出游戏”具有这一情况：三个外框合计宽305.952px，两端包围范围约299.452px，水平等距的结果是每段约−3.249886px。当前没有打开的编辑器窗口，因此只确认这组已保存的数据可以复现原因，不能断言用户当时的选区就是这一组。

- 等距现在允许负间距，即沿所选方向的外框投影有重叠。保持两端控件及所有控件尺寸不变，只调整中间控件的位置。
- 这组三个按钮等距后，设置按钮横坐标从1690px变为约1696.249886px，两端保持原位。第二次执行无需调整，也不增加撤销步骤。
- 水平与垂直独立判断。三个等宽同列或等高同行控件在对应轴本来已经均匀重叠时，允许点击并提示“无需调整”。
- 选中多个控件后，布局栏直接说明两个方向的间距或不可用原因。等距按钮保留详细悬停说明；禁用按钮外层可用键盘聚焦读取原因。悬停不会改变布局栏高度。
- 严重重叠、尺寸悬殊，导致固定两端后无法保持控件前后顺序的情况，仍会明确提示先拉开两端。异宽控件压到同一边缘可能在坐标换算后交换顺序，也不自动移动。
- 隐藏、锁定、自动排列父级、参数控制的位置、滚动容器边界、继承方案覆盖数量等原子保护继续生效。参数控制的两端保持不动时，不会阻止中间普通控件分布。

这里的“重叠”指选中方向的外框投影，包含图片按钮透明边缘；不等于可见图片一定重叠。想得到正的空隙，可以先把两端拉开，再执行等距。

## 实现范围

`src/core/ui-arrange.ts` 继续按世界外框计算间距并换算回各自父容器坐标，显式固定首尾；返回本次分布轴与间距供工具栏说明使用。精确同轴、同尺寸的情况直接视为无需调整，避免浮点累计误判。

`src/renderer/UiLayoutToolbar.tsx` 使用同一份计划计算启用状态与说明；`ui-layout-toolbar.css` 只增加禁用按钮说明容器的布局和焦点样式。未修改工程结构、运行时或作者工程。
