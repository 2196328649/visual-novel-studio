## 1. 采用的方向

以已经选定的折叠分组为基础，借鉴 UE Details 的分类和按上下文显示属性、UMG 的父容器布局关系，以及 Unity Inspector 的分组和 Prefab 覆盖标记。近期目标是统一属性编辑体验；可复用复合控件、公开参数和模板更新传播作为后续能力明确设计。

通用化应同时覆盖三个方面：

- 作者学会一次文字、颜色、位置、绑定和恢复操作，就能在适用的控件及内部部件中复用。
- 新控件复用已有属性语义、字段和分组，只增加它特有的内容编辑器。
- 同一字段的显示值、来源、修改范围和实际效果能够对得上。

不采用“一张表显示所有属性”的做法。没有文字的进度条不出现字体；普通文字不出现按钮悬停状态；列表的内部模板与整个列表保持明确范围。当前能力表和有效值解析仍有审查发现的不一致，复用前需要修正，不能把已有函数视为全部正确。

## 2. 通用面板的结构

顶部显示对象名称、类型和当前编辑范围，例如“存档列表 › 条目模板 › 摘要”，必要时注明影响此列表的所有条目。页面设置仍与控件设置分开；改变对象不会悄悄改成编辑页面或共享预设。

分组顺序保持一致，默认展开组随任务调整，用户操作后记住偏好：

| 分组 | 共用内容 | 按当前对象显示的内容 |
| --- | --- | --- |
| 内容 | 显示什么、从哪里取得 | 文字、图片素材、参数值、列表内容来源；复杂素材清单提供管理入口 |
| 位置与大小 | 位置、尺寸、单位、父对象 | 自由位置或排列中的附加偏移；容器才展开子项排列、间距、裁剪和滚动 |
| 外观 | 字体、颜色、底图及效果中的适用项 | 按钮集中选择状态；滑条显示轨道／填充／滑块；文字显示排版和文字效果 |
| 交互 | 显示条件、可操作条件及可用事件 | 按钮点击、输入提交、滑条改值、列表选择；复杂事件可定位到已有蓝图 |

文字初次编辑可展开内容与外观，图片可展开内容与位置。关闭的组显示“160×40”“点击打开设置”等真实摘要，同类对象之间保留分组和状态。没有适用字段的组可以省略；已保存但暂不适用的设置需要可查的说明，不因隐藏而清空。

字段常态为“名称＋数值＋单位”，位置和宽高等可成对排列。只有单独设置时才显示恢复入口；来源或限制影响理解时再显示短说明，例如“沿用页面字体”“设置 60，当前显示 21，受高度限制”。不常驻两套数值，不在每行堆放来源、绑定、收藏、关键帧等一排按钮。

可绑定字段提供“跟随参数”及来源定位；只读运行状态放在检查信息中。复杂条件、九宫格、描边和阴影在相关位置按需展开，避免再增加一个全局“常用／高级”切换层。属性搜索可接入这套字段目录；收藏和批量属性编辑排在基础操作稳定之后。

按钮状态在外观组内切换并同步样例。名称需区分游戏中的状态和编辑器的选择，例如“普通、鼠标经过、按住、开启／当前项、不可用”；最终词语应按按钮语义确定。“未单独设置”直接说明真实来源，例如“沿用鼠标经过的图片”，不让作者自行推算回退顺序。

## 3. 父容器决定布局解释

UE UMG 的 Slot 是很有价值的参考：放进 Canvas 和 Grid 的子控件面对不同布局问题，因此 Details 显示不同字段。本项目可以借鉴上下文表达，但必须遵守当前自己的布局计算。

当前 `src/core/ui-layout.ts:105` 在所有布局中仍计算子项的 `x/y`、锚点、宽高，再叠加父级排列的 slot；`:111` 按横排／竖排生成 slot。因此横排／竖排时不能直接隐藏 X/Y，或声称它们已失效。建议表述：

- 自由布局：显示“相对父内容区的位置”和宽高。
- 横向／纵向排列：优先显示排列顺序、尺寸，X/Y 显示为“排列中的附加偏移”，锚点等仍保留在更多布局中。
- 选择父容器：显示子项排列、间距和内边距；选择子控件：显示父对象及其布局来源，并可定位到父级修改间距。
- 背景子对象不参与前景排列和滚动，应显示实际规则。

如果未来新增由容器完全决定子项尺寸或网格行列的布局模式，再按该模式显示对应字段。不能在此次面板整理中暗中改变现有横排／竖排语义。

## 4. 把值、来源与恢复说准确

“来源”至少要区分以下情况，不能都写成“继承”：

| 情况 | 面板应表达的意思 | 恢复／修改边界 |
| --- | --- | --- |
| 页面主题与控件本地样式 | 沿用页面字体，或当前控件单独设置 | 清除本字段设置后沿用对应默认规则；不是清空整个 style |
| 基础界面方案中的控件 | 控件来自某方案，或当前方案已有整控件覆盖 | 目前按整个控件覆盖；恢复整个控件与恢复某项样式是不同操作 |
| 玩家剧情图节点外观预设 | 当前节点使用哪个预设，编辑预设影响哪些节点 | 使用已有解析及来源规则，不把选中节点自动转为修改预设库 |
| 参数／系统内容 | 来源是音乐音量、某参数、当前对白等 | 改显示值、换来源、修改参数默认值分别表达；失效引用明确标出 |
| 动画／事件的临时覆盖 | 当前运行实例由相关逻辑控制 | 有可观测证据时展示运行结果；不把临时结果写回设计稿 |

现有 `UiInstance` 在 `src/core/model.ts:759` 按完整控件替换上级同 ID 对象，`:862` 第一次编辑时完整克隆。它不是 Prefab 的逐属性覆盖。近期可提供准确来源说明、单项样式恢复和整控件恢复；若要承诺“改了文字后，其他属性仍持续跟随模板”，需另做差量覆盖模型与迁移设计。

“恢复默认”必须说明恢复到哪里。修改组的操作只影响组内归属字段，外观恢复不清除图片适配、绑定和交互。上下限等需成组校验的设置仍一次提交，一个操作对应明确的撤销范围。

## 5. 特殊控件与复合控件

近期的特殊控件继续使用专用编辑器，但共用文字、图片、布局等字段。例如存档列表：

1. 选择整个列表，编辑行列、间距和分页。
2. 进入条目模板，选择缩略图、章节、摘要等部件。
3. 选择“摘要”时，右侧使用熟悉的文字内容／字体／位置字段，并注明影响此列表的所有存档条目。

剧情图保留已完成的四组专用结构，接入共用字段操作、来源与范围提示即可。普通子对象属于整个控件的子树，不等同于每个重复条目的内部部件，不能直接把“添加子文字”当成条目模板实现。

后续真正增强通用性的能力是“可复用控件模板”：作者用图片、文字、按钮和容器组成一个控件，对外只显示常改设置，双击才进入内部结构。例如一个音量调节条对外只显示标题、绑定参数和外观样式，内部包含标签、轨道和滑块。

需要保持三种概念分明：

- **外观预设**：复用字体、颜色、图片等外观，不代表完整结构或行为。
- **子树组合与复制**：组合现有子对象；复制后是独立副本，不会自动同步更新。
- **可复用控件模板**：复用结构和行为，定义对外设置／事件、本地覆盖，以及模板更新如何传播。

最后一项需要稳定的内部对象身份、实例映射、公开参数与事件、引用重映射、应用／还原、删除和版本兼容。现有页面输入输出契约不等于控件公开参数。近期面板可预留专用编辑扩展位置，但不能把现有复制或界面方案继承改个名称就宣称具备完整模板能力。

## 6. 实现边界与代码基础

优先复用 `ui-properties.ts` 的稳定属性 ID、类型、单位、素材类型及校验，以及 `ui-control-properties.ts` 的实际输入模式解析。增加面向设计编辑的薄适配层和呈现信息，避免在不同面板再各造一套类型、默认值和绑定规则。

建议责任划分：

1. **属性语义**：继续由共享定义及真实渲染／运行解析负责，修正已发现的能力和默认值差异。
2. **设计编辑操作**：取得设计值和来源，执行修改、单项恢复、分组恢复及需要原子提交的操作；统一走既有草稿、保存保护和撤销入口。
3. **面板呈现**：按对象及任务展示分组、短标签、条件字段和专用编辑器；同一字段操作供各面板复用。

`applyUiPropertySnapshot`（`ui-properties.ts:293`）只用于私有渲染快照，不能直接作为通用设计写入器：空 path 的 visible／enabled／当前值不会被它写入，text 还会删除系统 binding。运行时可写不等于允许把状态直接保存为设计字段。

绑定入口统一时也要识别现有自动生成的绑定和用户编写的蓝图；当前 `createUiParameterBinding` 会创建 0.05 秒定时更新逻辑，不能仅搬动按钮后继续重复生成。调度方式改变属于另一项行为与性能工作，本次无性能测量。

先解决审查中的参数可信度问题，再将常用控件接入这套分组和字段操作，随后处理特殊条目模板。整个约定范围实现完成后，按用户要求统一编译、验证和验收，覆盖预览／游戏效果、保存重开、撤销、失效来源、恢复范围以及同类切换的任务连续性。
