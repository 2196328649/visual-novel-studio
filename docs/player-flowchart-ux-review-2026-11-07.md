# 玩家剧情图的属性与交互审查

2026-11-07。用户要求开启子代理，审查「界面」里的剧情流程图 UI，并提出更易理解的设置方案。随后用户授权“先优化”，第一批已实现并通过构建、1766项单测、3项桌面与3项游戏专项，见 `player-flowchart-optimization-2026-11-07.md`。下文保留审查依据和后续待讨论规则。设置页禁用按钮被当成导航出口是另一项已完成修复，记录见 `ui-flow-exit-states-2026-11-07.md`。

## 审查范围与结论

子代理和主代理依据当前源码、交接文档以及历史桌面截图交叉核对。主要对象是界面设计器的 `flowchart` 控件，即玩家在游戏中查看和重玩剧情的地图；作者连接段落的「流程图」工作区、菜单页面的按钮出口是另外两个编辑对象。本轮没有操作真实用户工程，也没有把历史截图当作当前构建验收。

当前属性沿用普通列表、普通按钮的分组，再叠加流程图字段。因此作者容易分不清正在修改整图、一个节点还是共用样式，部分输入的显示值还与实际默认值不同。优化重点应是操作对象和生效结果清楚，而非再添加更多选项。

## 已核实的问题

| 问题 | 证据与影响 | 建议处理 |
| --- | --- | --- |
| 分支图出现不适用的列表字段 | `UiAppearance.tsx` 显示「每行数量」「每页行数」；`storyFlowLayout` 的分支布局不读取这两个值。 | 展示方式选「分支图 / 目录列表」；只显示当前方式实际使用的字段。 |
| 面板默认数字不是真正默认数字 | 属性间距回退为 12，分支布局回退为横向 100、纵向 90；条目尺寸回退显示 0，布局实际默认 350×80。 | 使用同一处默认值来源，显示实际数字和像素单位，提供恢复默认。 |
| 方向文案与设置冲突 | 「横向分支图」还可设为「从上到下」。 | 改为「分支图」，方向单独用两个示意选项表达。 |
| 文字对齐控件未接通分支图 | `UiInspector.tsx` 允许选 `style.align`，`UiFlowPreview.tsx` 和游戏的 `vn_styled_button` 仍固定居中。 | 首批接通整段文字在节点中的左右/中对齐，编辑器与游戏一起验收；明确多段文字仍保留现有顺序和间距。 |
| 同一个字段多处编辑，样式来源不透明 | 「节点文字」基础字号/颜色与「外观与状态」写同一字段；共用框样式的编辑下拉只切换编辑对象，不是给选中节点应用。 | 合并入口；顶部区分整张图和当前节点。节点直接选「使用样式」，另设「编辑共享样式」并显示影响数量。 |
| 多字体文字要手写分隔符 | `UiFlowNodeText` 要求输入全角 `｜`，按末尾对应文字段；一次显示所有节点，缺少查找。未覆盖的分段颜色仍显示白色，实际可能继承其他颜色。 | 点节点后逐段输入、设字体和字号，直接预览；继续兼容原存储语法。显示继承来源，提供恢复继承，节点列表可搜索。 |
| 不清楚节点为何出现或消失 | `storyMenuEntries` 按章节/小章节/段落的公开设置生成条目；相同入口由更具体条目覆盖。界面属性只能改已出现的条目。 | 提供「显示哪些剧情」入口，显示来源路径、显隐和相同入口的覆盖说明，可定位剧本。 |
| 普通按钮状态不能代表玩家进度 | 预览可把全图一起设为选中，导致所有节点同时出现当前位置标记。「未到达图片」存在时会隐藏文字。 | 预览提供「全部可见 / 部分已到达 / 当前节点」，仅指定一个当前节点；明确图片与标题的现有关系。 |
| 「跳转」没有说明会重新开始 | `VnStoryStart` 实际调用 `Start` / `full_restart`，解锁来自跨存档的 `persistent` 到达记录。 | 集中为「玩家操作」，准确写成「从此处重新开始」「曾经到达后可进入」，用简短说明交代本局进度。 |
| 连线、装饰和滚动设置混排 | 连线图片与节点底图混在一起；「横向滚动条」也可用于纵向；连线支持颜色但缺专用颜色字段。 | 单独「布局与连线」，按形状、粗细、颜色、可选图片排列；滚动区域和标记区域在画布高亮，数值供精调。 |

## 建议的面板结构

按用户任务组织为四组，而不是按数据字段分类：

| 分组 | 用户主要操作 |
| --- | --- |
| 内容 | 选哪些章节/段落显示；查找、定位节点；编辑当前节点的多段文字。 |
| 节点样式 | 当前节点使用哪种框；字体、底图和状态；显示继承来源及修改共享样式的影响。 |
| 布局与连线 | 排列方向、节点尺寸、间距；折线/直线/曲线、线宽、颜色；手动位置与恢复自动排列。 |
| 玩家操作 | 可进入范围、未到达时怎么显示、当前位置、从节点重玩及重玩前确认。 |

选中画布节点后，右侧顶部保留「当前节点：记 第一回 · 醉梦」及其文字段和使用样式。点空白处返回整张图设置。修改共用样式时明确显示「影响 12 个节点」，并可查看使用位置。数字输入旁能看到默认/继承来源，恢复按钮仅清除该项覆盖。

连线形状用简单图例；节点样式示例显示真实节点文字及有效字体，避免仅用样式名代替预览。滚动条、显示区域、当前位置标记的位置设置在画布中有对应高亮，保留精确输入框。

建议将界面控件称为「玩家剧情图」并说明「供玩家查看和重玩剧情」。作者的顶层工作区可以继续叫「流程图」，现有页面名称由作者保留。

## 建议实施顺序

1. 修正无效字段、默认数字、方向文案和对齐；同一默认值由布局与属性共同读取。
2. 合并重复入口，增加当前节点的文字/样式卡、真实预览及恢复继承；高级参数默认收起。
3. 整理连线与玩家操作分组，添加进度预览场景，再完善内容选择与来源定位。

第一批保留工程格式、分段对应规则、跨周目解锁和点击重玩的运行语义；预览、游戏结果、保存重开和旧工程应共同验收。代码拆分按内容/样式/布局/玩家操作各自职责进行，避免继续扩展 `UiAppearance` 的大条件块。

## 改规则前需要讨论的事项

- 是否新增「保留当前参数并跳到节点」；目前点击是重玩，两者不应混为一个含糊选项。
- 是否新增本存档解锁或自定义条件；目前规则是跨周目曾到达。
- 多段文字是否升级为具名文字段；第一批可以改善输入方式并保持从末尾对应的兼容规则。
- 未到达图片是否改为显式的「图片自带文字」选项；现有模板依赖隐藏标题的规则。
- 作者的剧情组是否映射为玩家地图的折叠分组；当前两者独立，不能自动把所有作者分组公开给玩家。

以上是需要选择的新能力，不阻止先修正显示值和整理已有操作。
