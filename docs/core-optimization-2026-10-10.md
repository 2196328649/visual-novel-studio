# v0.8.1 底层优化

保留 TypeScript、React、Electron 和 Ren’Py 的现有分工。本次测量发现主要开销来自整份工程复制、重复参数生成和主线程图片解码，因此直接优化这些路径；工程文件格式保持兼容。

## 编辑与撤销

- 常规工程编辑、界面草稿、数值拖动使用 Immer 事务，只复制变化分支。编辑失败不会污染已有历史，无变化的提交保留原引用。
- 显式复制、粘贴和资源编辑使用能识别事务草稿的复制函数，避免把 Proxy 传给原生 `structuredClone`。没有替换全局 API。
- 界面草稿比较利用引用共享，避免序列化整份工程；三方合并仍保留同时导入的素材及其他工程修改。
- 同一字段在 700 毫秒内连续输入合并为一次撤销；不同字段、集合操作和显式独立操作分别记录。保存、丢弃和重做继续使用独立草稿。
- 章节演出生成器对每个嵌套画面只解析一次，并建立参数查找表，避免逐个公开参数重复解析同一对象。公开参数、默认值和连接不变。

## PNG 分析

PNG 解码和透明边界扫描放入最多两个后台工作线程。导入和自动发现素材复用已经得到的尺寸，避免再在主线程重复解码。补全旧版立绘元数据时限制读图并发，并使用最多 128 项、按文件大小和修改时间失效的缓存。

线程空闲后释放，单个任务有超时；坏图只影响本次任务，后续图片可继续处理。压缩数据使用独立副本传输，不分离导入方持有的缓冲区。桌面打包单独包含工作线程文件，并通过 `asarUnpack` 提供真实文件路径。非 PNG 图片仍使用现有原生读取流程。

## 本机测量

真实窗口使用同一份哀鸿模板副本、本地编译界面、独立配置和相同键入方式。下表每项为有限样本，响应还受工程内容和机器负载影响。

| 操作 | 修改前中位数 | 修改后中位数 | 样本数 |
| --- | ---: | ---: | ---: |
| 界面控件名称输入 | 41.9 ms | 29.0 ms | 各 20 次 |
| 界面显示文字输入 | 37.0 ms | 23.8 ms | 各 20 次 |
| 剧本输入，显示演出 | 108.4 ms | 35.4 ms | 各 24 次 |

界面测试使用 297 项素材、137 个组件。长文本测试包含 8,027 个字符、73 句对白和 297 项素材；章节参数优化后的显示／隐藏演出输入 P95 为 40.5／41.1 ms，两组均无超过 50 ms 的长任务。长文本“修改前”是本轮章节参数优化前的测量，该次运行因超出原有性能门槛停止，不能算作完整功能验收；优化后完整通过原有门槛。

数据更新微基准另用 500／5,000 行工程、各 80 次更新：中位耗时分别从 5.003／20.050 ms 降至约 0.020／0.019 ms。三张 2048×2048 PNG 的主线程最长调度间隔从 445.66 ms 降至 16.24 ms。这些数字只代表被测数据操作，不是整个编辑器的加速倍数，也不涵盖文件复制和保存耗时。

## 验证与测试窗口退出

1,033 项单元测试和 TypeScript 检查通过。真实窗口已验证界面输入、数值拖动、排序缩放、资源类型、组合轨道隐藏／独显、音频、嵌套坐标拖动和保存重开。长文本验收覆盖两种显示模式、中文换行、撤销重做，以及原有对白 ID、演出和配音的保留。蓝图界面的六组验收覆盖参数同步、资源选择、错误定位和保存重开。

自动验收只在确认独立配置目录正确后销毁该实例的测试窗口，再等待 Electron 退出。界面验收故意留下未保存草稿，确认关闭流程不会再停在“是否保存”窗口。日常编辑器的保存提醒继续保护未保存作品。

复现命令：

```powershell
pnpm test
pnpm build
pnpm exec tsx scripts/verify-ui-responsiveness.ts
pnpm exec tsx scripts/verify-text-responsiveness.ts
pnpm exec tsx scripts/benchmark-project-edits.ts
pnpm exec tsx scripts/verify-image-metadata-desktop.ts
```

打包后可将 `VNS_INSTALLED_EXE` 指向待测程序，再运行图片或界面验收。图片验收经过真实桌面 IPC，覆盖旧版立绘补全、大图、全透明图、坏图恢复、无重复原生解码以及保存重开；测试配置与作品都位于独立目录。
