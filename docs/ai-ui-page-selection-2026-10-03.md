# AI 识别当前界面页面（2026-10-03）

过去只发送所选控件、蓝图和动画，空页面没有对象可供助手判断“当前页面”；自定义页面的控件类型也只写 `custom`，不能直接表达正在编辑的页面。现在设计和事件图都会同步 `selectedUiPage`，包含页面 ID、普通页面的方案 ID，以及 `design/events` 模式。助手中明确显示页面、方案和模式；离开界面工作区时清理。

标准页面以 `ui:preferences` 等 ID 定位，默认方案是 `base`，自定义页面使用其真实 ID，不带方案。发送请求时保留页面选择及工程快照，后续切页不会改变已发送请求的目标。元数据还提供当前页面设置的写入路径；派生方案指向自己的 `instances → ID → pages`。父级结构不存在时仍须先读取并补齐，元数据不会自动修改工程。

页面、方案已删除、身份有歧义或与工程快照不匹配时，标记 `selectionUnavailable`，不猜另一个同名对象。所选控件按当前页面的有效控件解析，保留本方案覆盖，排除其他页面或已隐藏控件的残留选择。旧调用未提供页面选择时保留原组件解析方式。普通、截短和最小请求上下文都保留该字段。

## 实际操作发现的同名方案问题

编译版验收第一次实际应用建议时失败。不是 UI 切页改变了工程，而是 `applyTextScript` 对 `@界面实例：同名方案【child】` 的解析使用“ID 或名称匹配”，提前选中名为“同名方案”的父方案。应用前的文本转换因此把活动方案变为 `parent`，触发原有过期保护。

现改用现有的稳定引用解析器：明确 ID 优先且不可失效后回退同名；没有 ID 时名称必须唯一。裸 ID、默认/无仍可使用，显示名称变化不改变目标。文本往返、AI 修改准备及实际应用都覆盖了此修复；项目冲突指纹规则没有放宽。
