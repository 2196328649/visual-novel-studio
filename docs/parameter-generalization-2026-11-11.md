# 通用参数集、独立保存和恢复行为

日期：2026-11-11。

用户确认：不增加“更多设置”分类，设置也是通用变量，其中一些只供蓝图使用。此次统一参数集和所有新建入口，并移除自定义参数自动生成的设置菜单。

## 使用方式

- 参数集只有“新建参数集”入口。名称、默认保存方式在同一个创建窗口中填写，取消不创建任何数据。
- 参数集负责整理变量，不再要求选择剧情或设置用途。“新参数默认配置”只影响之后创建的变量。
- 每个参数独立选择“随存档保存”或“保存在本机”。“恢复初始设置”折叠项单独控制它是否参与玩家的设置恢复操作。
- 剧情、蓝图和界面使用同一个变量。变量可以仅供蓝图使用，不需要界面控件。
- 自定义参数不会自动添加到游戏设置页，也不再生成“更多设置”入口。内置13项玩家设置和作者已经放置的控件继续工作。
- 需要玩家输入时，在参数详情展开“界面控件（可选）”，选择目标页面并添加控件。支持标题、设置和自定义页面；已有控件则直接定位，不重复创建。
- 蓝图“本机变量”决定本机保存，“作品状态”决定随存档保存，均可归入任意参数集。蓝图新建变量默认不参与设置恢复。控件属性右键及关联面板也使用相同的保存、恢复字段。

保存方式和设置恢复可以任意组合：

| 保存方式 | 参与恢复初始设置 | 适用示例 |
| --- | --- | --- |
| 随存档保存 | 否 | 当前剧情进度、蓝图计数 |
| 随存档保存 | 是 | 当前存档内可恢复的界面选项 |
| 保存在本机 | 否 | 跨周目解锁、蓝图专用长期记录 |
| 保存在本机 | 是 | 玩家主动设置的显示或操作偏好 |

改变参数集不改变参数本身的行为。移动、改名、复制和移除分组时保留变量值及有效保存、恢复配置；移动或移除组仍保留原变量ID和引用。复制创建独立ID，剪切粘贴移动当前变量，不用剪切时的旧快照覆盖后续编辑。

## 实现与兼容

`ParameterSet.defaults` 只定义新建默认值；`Variable.persistent` 和可选的 `Variable.resetWithSettings` 定义运行行为。旧 `kind` 只用于兼容读取，旧参数尚无恢复字段时继续采用原设置组的恢复规则。打开、预览、编译不自动改写工程；实际移动等操作会保留当时已经生效的恢复规则。

各新建入口共用行为字段。属性绑定表单改变分组后保留已经选择的保存、恢复方式，作者可明确点击“采用分组新建默认”。新参数初值为0、关闭和空文字时均原样保留。输入法确认回车不会提前提交创建窗口。

通用工程编辑也采用这些规则。新变量在目标分组存在时使用当时的新建默认，后续修改分组默认不追溯改变它；先声明变量、再声明分组也可处理。替换已有变量对象或移动分组保留有效恢复规则，非法修改在整批校验中拒绝。

界面参数控件的范围只约束其输入，不因某个变量属于旧设置组就限制蓝图数据。显式控件仍检查有效范围及关联初值。恢复设置会先校验所有参数恢复值，再修改内置音量、静音、显示选项和自定义变量；动态范围无效时整次拒绝，不留下部分恢复状态。

旧 `setting.visible` 元数据继续可读，但不再自动生成自定义设置控件。旧存档若恢复到 `vn_parameter_settings_menu`，兼容入口转到正常设置页，不重新引入“更多设置”。
