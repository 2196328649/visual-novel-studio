# 流程图分层与剧情打组

2026-11-07，用户确认「先进行优化看看效果」后实施第一批流程图整理。顶层显示启动、菜单和游戏内容，剧情按小章节与剧情组逐层进入。沿用现有运行数据和 Ren'Py，不新增第二套剧情执行模型。

## 使用方式

1. 顶部打开「流程图」，双击「游戏内容」，再双击小章节卡片。
2. 在空白处拖框选择剧情节点，或按 Ctrl 多选；右键「打组为剧情组」，也可点工具栏「打组」或按 Ctrl+G。
3. 输入名称后，所选内容收成一张组卡片。双击、选中后按 Enter，或点卡片右侧箭头进入。组内可继续打组。
4. 点击上方面包屑、「返回上一级」或 Alt+↑ 返回，恢复上一层的选择、缩放和平移位置。
5. 选中组可重命名或「解组，保留内容」。解组保留当前内部编辑；选中组按 Delete 不删除其内部剧情，也不误断组边界连线。
6. 搜索支持组名、小章节、剧情名称和对白；结果带所在位置及对白摘要。跨章节引用、内部问题与全局问题列表可以直接定位组内节点。

第一版只把同一小章节、同一层级的完整节点或子组一起打组。小章节仍是原有章节结构的一部分，组可嵌套。组内复制节点、在模块编辑中沿已有段落插入或粘贴内容，会继承该段落的组归属。

## 界面与连接

- 顶层启动路径使用实际可达顺序给未手工摆放的节点提供默认位置；已有手动坐标继续保留。切换层级、搜索、查看属性不会写入布局。
- 连线增加终点箭头，选择、计时结束、页面关闭、演出完成、取消、调用返回等出口标明触发原因。普通顺序线减少重复标签。
- 返回标题指向标题菜单。是否重播开场按启动执行时机显示；动态调用返回明确写出「运行时决定」，不伪造固定目标。
- 向后连线和自身循环绕过两端卡片。共享选线逻辑支持多段曲线，普通蓝图保留原有连线外观。
- 组外保留跨边界的真实多入口、多出口。即使两段剧情同名，端口仍按真实节点 ID 与出口 ID 区分。
- 组内显示「来自」「前往」等外部引用；点击可以追踪原节点。需要连接组内其他位置时先选择具体目标，不自动接到第一段。
- 故事入口显示明确标识，改入口需展示旧节点和新节点并确认，操作可一次撤销。
- 属性栏可收起。「适应全图」用于总览；常规进入和搜索定位保持较大比例。大图全览仍可能缩小文字，可进入组或定位节点查看。
- 「整理当前布局」只整理当前层，可一步撤销；返回目标引用随剧情出口放置，全局返回标题仍保留回返关系。

## 数据边界与代码组织

新增可选 `storyGroups`，保存稳定组 ID、名称、小章节、直接成员、父组和组卡片位置。成员只属于一个直接父组，校验缺失成员、跨章节归属与包含循环。原剧情循环允许保留。

`story-groups-schema.ts` 负责结构校验，`story-groups.ts` 负责打组、解组及归属维护，`story-graph.ts` 负责画布投影；卡片、对话框、视口会话和返回线几何分别独立。节点复制复用已有 `copyStoryModule`，没有保留另一份重新生成台词／选项 ID 的实现。

组不改变原剧情节点、台词、选项 ID、`sceneId`、参数作用域、调用栈或入场执行时机。保存和撤销包含分组资料；纯文本应用到现有工程按稳定 ID 保留仍存在的成员，删除或移出小章节的成员会清理归属。**把纯文本单独导入新工程不携带分组资料**。编辑器剧情组也不会自动变成玩家剧情回顾图的节点。

查看层级和视口保存在本机编辑器会话中，随项目恢复，不进入游戏运行数据。恢复时属性依据当前画布选择显示；旧主编辑器选择不会覆盖组内当前节点。复制后选择读取最新工程，避免刚新增的 ID 在旧快照中查不到。
