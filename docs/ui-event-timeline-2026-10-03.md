# UI 事件图内的演出时间轴 · 2026-10-03

接续 UE5 Widget Blueprint 式控件事件工作流。本轮补齐原先存在但未接通的“添加时间轴 → 双击编辑”入口，仍在当前 UI 草稿里完成编辑与保存。

- 双击时间轴调用节点进入素材、预览、轨道、属性面板。可编辑图片、文字、时长和输入参数，播放或移动播放头。
- 支持展开标题的内部时间轴，逐层返回后重新选中实际调用节点。导航记录调用节点 ID，因此重复引用、重定向、撤销删除、组件消失时不会误跳到另一个调用。
- 公开或取消参数时，在同一次草稿提交中同步父调用引脚。测试传入参数只影响当前预览，组件默认值仍由片段属性编辑。
- “查看组件连线”和非线性时间轴提示中的“打开蓝图”进入当前组件的节点视图，保留当前片段；不会误返回页面事件图。组件节点视图固定当前图，隐藏跨图选择器和新建图入口。
- 返回事件图后仍可接后续执行节点；页面、控件选择和草稿保留。支持 UI 保存、重开、放弃和独立撤销重做。AI 当前对象上下文随当前时间轴与片段变化。

## 原生运行时修复

实际运行桌面保存的主菜单按钮图发现：图片与嵌套标题时间轴启动后，末尾等待不会结束，后续“隐藏文字”节点无法执行。失败报告：`artifacts/ui-event-timeline-runtime/2026-10-02T16-17-33.631Z/report.json`。

原因是时间轴截止时间使用 `renpy.get_game_runtime()`，该 API 只读顶层剧情上下文，明确不计算菜单及新上下文内等待。改为 `vn_bp_clock()`，读取 `renpy.game.context().runtime`；它在当前执行上下文内累计等待时间，同一上下文的父子时间轴共用计时，顶层剧情仍使用原有 runtime，保存恢复沿用上下文计数。替换了片段截止时间、内部间隔与末尾等待的时钟。

修复后原生 1 用例 / 5 断言通过，实际点击到隐藏完成约 4.3 秒；测试记录确认父时间轴和内部时间轴都执行，页面显示没有误触发点击事件。另回归剧情内部间隔和末尾等待中的真实保存/读取、嵌套重叠、已传入时长与外部变量隔离，以及点击跳过行为。

## 范围限制

这里是可由 UI 事件调用的**演出时间轴**，用于画面、文字对象、角色和声音，尚不是 UE5 UMG 式控件属性动画轨道。控件显示、文字和位置等仍通过事件图里的控件属性节点控制。更多控件事件和预设动作节点仍待继续；交互预演也不是完整 Ren’Py 舞台模拟。

本轮只操作隔离开发夹具，未替换已安装版，未恢复用户已停止的原作电脑操作。旧选择验收中的剧情流程全选删除问题仍未处理，不能宣称全部桌面脚本通过。整体持续目标未完成。
