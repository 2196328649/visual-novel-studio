# 结局指令重复与文本卡顿修复（2026-10-05）

## 原因与修复

文本编辑、导入和部分演出编辑路径重建 `scriptText` 时漏掉 `standaloneSyntax`、`performanceSyntax`。保存及自动保存会调用项目迁移器，把新版 `@独立演出：结局演出` 再当成旧版调用，插入新的 `@结局演出`。旧开发版在用户自动保存副本上编辑并保存一次，调用数从 12 增加到 24，见[复现记录](../artifacts/ending-freeze-baseline.log)。

统一用 `currentScriptText` 写入当前语法标记；旧项目仍正常迁移，不在 schema 中默认标记。独立演出迁移也识别前面已有的显式调用，避免旧结局迁移刚生成的“调用＋声明”被再次展开。作者有意重复的演出不会自动删除。

性能记录另外发现 `rawSavedBlueprintAction` 对普通逻辑节点反复尝试 JSON 解析并抛出异常；预览及诊断均会走到该路径。现在只解析确有序列化动作的 `savedAction` 节点，保留损坏动作的校验处理。
