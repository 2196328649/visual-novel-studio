# 可视化视觉小说引擎：AI 执行规划

状态：目标正在执行。以当前代码和实际验收报告接续开发；已纳入动态演出、点击互动、小游戏和 UE5 风格工作台要求。

当前增量：场景、角色、界面和效果已采用数据驱动的实例/继承模型，并提供中文文本指令与编辑器属性面板。仍需完成《哀鸿》风格模板和完整能力逐项验收。

## 目标

由 AI 负责设计细化、环境配置、全部新增代码、测试、修复、文档和打包，交付面向其他创作者的全可视化视觉小说引擎 1.0。用户无需编程、执行开发命令或手工集成模块。

首发范围：Windows 桌面编辑器、中文界面、离线创作、Windows 独立游戏导出。

## 必需功能

1. 项目与素材：新建、打开、保存、导入图片和音频、角色与表情管理、资源重命名和引用检查。
2. 剧本：章节、场景、段落、对白、旁白和配音。连续对白以列表编辑，剧情图以段落和分支为单位。
3. 蓝图：开始、段落、选项、条件、状态修改、跳转、调用、结局；支持搜索、自动布局、折叠和可复用子图。
4. 状态：好感度、开关、物品标记、全部满足或任一满足的组合条件，通过表单配置；区分存档状态和跨周目记录。
5. 舞台：拖拽背景和角色，配置位置、缩放、图层、表情、音乐、音效和转场；支持角色关键帧、平移缩放、旋转淡入淡出、镜头运动和震动，操作写入当前剧情动作。
6. 界面：通过模板和组件可视化配置标题页、对话框、选项、存档页和设置页，并绑定标准行为。
7. 试玩与排错：实际游戏运行、指定测试状态的片段试玩、运行位置与错误定位；预览和导出使用同一运行时。
8. 可靠性：撤销重做、自动保存、崩溃恢复、保存重开、缺失资源和无效分支提示、项目版本迁移。
9. 玩家功能：存读档、回滚、自动播放、跳过、历史记录、声音和文字设置、基础 CG 与音乐回放。
10. 发行：编辑器安装与升级、独立游戏打包、示例工程、简明中文文档、必要的许可声明。
11. 点击互动：在场景和人物上可视化配置热点、条件与事件，点击后能触发对白、状态修改和剧情分支，并能在蓝图中连接。
12. 小游戏：提供数据驱动的轻量互动模板，至少包含密码锁及一种限时或记忆互动；参数、成功、失败、取消分支均可视化配置，支持存档恢复与游戏导出。
13. 中文文本创作：直接导入 DOCX、TXT、Markdown 剧本，识别角色对白、旁白、标题与段落；提供中文文本编辑页面，通过文字插入或修改场景跳转、背景、BGM、音效和动态演出。复杂演出可配置为可复用实例，用“效果 名称”调用；输入 `/` 或全角 `／` 打开中文指令和资源选择窗口。支持随文字与光标更新的画面预览、音频试听、有效草稿直接试玩与导出，以及文本和图形视图的数据同步。

本次不包含云协作、账号付费系统、插件市场、内置 AI 内容生成、通用 3D 引擎或其他平台发行。

## 技术约束

- 在独立应用目录开发，保留当前 SDK 原文件。优先验证现有 Ren'Py 8.5.3 作为运行时。
- 编辑器优先采用 Electron、React、TypeScript 和 React Flow；具体技术由 AI 根据实际验证决定。
- 项目数据是唯一编辑源，使用版本号和稳定对象 ID。剧本、舞台与蓝图共享数据，生成脚本作为构建产物。
- 优先生成标准 Ren'Py 语句，先验证分支、存档和回滚；不能把临时画面预览当成真实运行。
- 中途试玩需要明确初始状态，不能假定跳到节点就能恢复全部历史。
- 保留发行版编译产物和存档兼容基线，验证改稿后的旧存档；重命名不能破坏引用，迁移失败可以恢复。
- 常用操作有合理默认值，中文输入正常；1280×720 和 1920×1080 下主要页面可操作且无内容重叠。
- 界面参考 UE5 的深色工作台、素材浏览、属性面板和蓝图布局，保持视觉小说工作流简洁且零编程可用。
- 使用成熟组件，自行实现和调试；不要求用户写代码、修改生成脚本或安装开发工具才能创作。

## 实例化设计约定

- 场景实例通过 `baseSceneId` 和 `parameters` 继承基础场景；场景跳转保存 `fromSceneId`、`toSceneId`、模式、时长、颜色和参数。
- 角色实例通过 `baseCharacterId` 继承表情与 `features`；角色功能由可复用舞台动作组成。
- 界面实例通过 `baseUiId` 继承组件，当前实例的同 ID 组件覆盖基础组件；标题、对话、选项、存读档和设置页面共用该解析结果。
- 复杂动画使用效果实例，文本以 `@效果：名称` 调用，避免把复杂参数散落在对白中。
- 继承链必须无循环；引用缺失、组件不合法和无效转场在问题面板中报错或提示。

## 执行顺序

1. 建立最小项目格式，生成、运行并导出具有条件分支的示例游戏，验证存读档和回滚。
2. 接入最小编辑器，打通新建项目、编辑、保存重开、试玩和导出。
3. 完成舞台、事件蓝图、界面编辑及其余必需功能。
4. 修复数据恢复、升级兼容与长篇性能问题，完成安装包、示例和文档。

AI 自主拆分任务，并行处理边界清楚的模块；统一集成和回归验证。只维护必要的任务清单、决策和已知问题。阶段完成后继续推进，原型和 MVP 不是最终完成条件。

## 完成标准

- 通过界面从空白项目制作含两个角色、三个场景、好感度、条件分支、三个结局和音画演出的作品，全程不编辑代码。
- 保存并重新打开后，内容、素材和连线完整；可以继续改稿、试玩和重新导出。
- 各分支结果、存读档、回滚和跨周目状态符合预期；片段测试状态与真实玩家存档隔离。
- 修改界面模板后，实际游戏和导出结果一致；所有主要控件真实可用。
- 通过界面配置并实际运行角色动态演出、镜头效果、场景和人物点击事件及小游戏成功/失败/取消分支，验证其状态恢复和独立导出。
- 用用户提供的中文 DOCX 验证原生导入、改稿、斜杠资源选择、实时画面、保存重开、真实试玩及导出；验证场景指令确实跳转目标剧情，复杂演出往返保留且对白仍可编辑，错误文本定位并阻止使用旧稿发布。
- 自动保存恢复、错误定位、资源引用、项目迁移和已声明的存档兼容范围经过实际验证。
- 用至少 100 个场景、1000 个段落节点的基准工程验证分层编辑、检索和保存，记录测试设备与性能。
- 编辑器及导出的游戏在不依赖开发目录的 Windows 环境中运行，交付可分发安装包和独立游戏包。
- 交付源码、示例工程、构建方式、中文使用文档、实际测试结果、已知限制和零基础用户验收流程。

未执行的检查明确标为待验证；不能把自动化检查称为真实新手测试，不能以占位界面或仅能运行示例作为全部完成。遇到真实外部阻塞，说明原因、已尝试的解决办法和所需输入，继续可独立完成的工作。
