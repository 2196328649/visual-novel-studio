# 流程全选删除与蓝图验收迁移 · 2026-10-03

修复主核对表中长期未收尾的剧情流程全选删除问题，并迁移两套仍使用旧入口的验收脚本。整体目标仍未完成。

## 实际原因与修复

起点的删除保护一直存在于 `Blueprint.tsx`：当前故事入口及 start 节点不接受画布删除。历史失败截图显示，删除后编辑器已经切换到了文本页，底部仍显示工程有一个节点；因此“画布节点数为零”并不证明起点被删除。

当前源码复现确认：只保留起点并清空 next 后，`projectToText` 正确生成显式入口和 `@跳转：无`。`applyTextScript` 却自动添加“故事结束”节点。`hasTextDraft` 比较往返结果时发现结构不同，于是误判有未应用文本修改，App 自动跳转文本编辑。

现在，带显式 `@入口` 的文本保留已声明的流程结构，不再自动添加结局；这与已有的“不自动补起点”规则一致。只剩起点、以普通段落为入口或以返回节点结束的已编辑流程都能稳定往返。没有显式入口的普通正文导入仍自动建立起点、结局并顺序连接。未修改删除权限、恢复历史或文本草稿自动提示规则。

新增三个结构测试验证上述行为，包括序列化相等、节点身份、章节结构、入口和编译文件保持一致。

## 实际编辑验证

`verify-blueprint-selection-editor.ts` 改为当前“蓝图 → 演出目标”入口，增加 dist 开关，并完整运行原先中断的剧情删除及重启段落。全选删除后留在流程图、只保留入口；保存、一次撤销、重做、再次撤销均与预期工程数据一致。此前七项节点/连线框选、混选、批量移动、折叠和缩放命中检查保留并通过。

`verify-blueprint-editor.ts` 从当前工作区创建蓝图，使用蓝图入门入口和素材浏览窗口。原有六项验收目标未删减：入门连线及角色站位、用户节点类型与数据线、调用接口同步及局部覆盖、素材诊断定位修复与编译、1024/1280/1920 宽度、保存重开与剧情/节点图切换。该脚本为 Vite 浏览器夹具，使用模拟桌面文件桥；不称为安装版或真实文件对话框验收。
