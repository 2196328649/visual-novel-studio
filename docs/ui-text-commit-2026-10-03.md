# 文字提交事件 · 2026-10-03

按 UE5 Widget Blueprint 的控件事件工作方式，补齐自由文字输入的 OnTextCommitted。可以将提交文字连接到界面文字、变量或判断节点，用执行线决定提交后做什么；OnValueChanged 仍负责输入过程中的实时反馈。

## 使用与约定

1. 在设计页摆放设置控件，绑定没有选项列表的 string 参数。
2. 切换事件图，选中左侧的“文字输入”控件，点击“文字提交时 · OnTextCommitted”。重复添加定位已有入口。
3. 连接白色执行线，再把“提交文字”或“提交方式”连接到需要的值输入。
4. 在交互预演中输入、按 Enter 或切换输入框；保存界面后写入工程。

节点 `eventTextCommitted` 的属性为 `componentId`、`uiInstanceId`，沿用当前页面与方案范围。输出 `exec` 为执行，`value` 为提交文字，`method` 为字符串 `enter` 或 `focusLost`。两个数据输出都是本次提交的快照，回调内修改参数不会改变它们。

Enter 结束本次编辑并只提交一次；点击其他位置或 Tab 结束编辑时提交 focusLost。文字没有改变也允许明确提交；点击当前输入框不会提交。初始化、内部值改变回调刷新、隐藏、禁用、离页、模态覆盖和读取存档不会主动提交。选项列表、数值滑块及布尔控件没有此事件。

## 实现边界

Ren’Py InputValue 不会随普通鼠标焦点自动停止编辑。新增透明的输入事件监视器识别实际点击与 Tab，在提交前结束当前编辑；界面刷新不经过此提交路径。源控件、页面和上层模态屏幕决定输入是否可用。提交打开另一页面时拦截同一鼠标按下/松开，防止操作落到新页面或底层按钮。自定义弹窗自身的输入框可以正常提交。

预演通过 DOM focus/blur 与键盘事件实现，Enter 后的 blur 不重复广播。输入法 composition Enter 已加保护，桌面测试使用模拟 composition 键盘事件；本轮没有操纵真实系统输入法，不能据此声称所有中文输入法均经过实际验收。

提交与值改变共用带本次事件数据的派发过程。既有同一事件入口等待交互时的重入保护仍生效，重复进入会被忽略；未新增通用焦点或拖放事件。AI 提示已同步真实字段及语义，未调用真实模型。
