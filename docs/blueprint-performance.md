# 蓝图流畅度与选择修复（2026-09-15）

本轮处理点选、拖动和参数输入卡顿，同时统一剧情流程与节点编程的框选行为。仅更新开发版，没有生成安装包或游戏导出包，测试使用独立工程与用户配置目录。

## 修复原因与行为

- 过去点选会给所有节点重建 `data` 和编辑回调，导致整图参数、资源和 UI 组件选项重新渲染。现在缓存未变化节点的内容；历史快照复制工程后也能复用，角色、素材分类、UI、调用接口、输入连线或诊断变化仍会刷新相关内容。
- 拖动中的坐标交给 React Flow 管理，避免每次鼠标移动执行整个编辑器的计算。拖动结束一次保存所有移动节点，撤销／重做恢复整组位置。
- 保留未变化连线与事件回调，平移不再触发每条线重新渲染。缩放只更新统一的点击宽度，连线的实际点击区域保持 28 屏幕像素。
- 节点编程显示时不再构建隐藏的剧情流程图。
- 框选采用部分相交；连线使用实际贝塞尔曲线判断，不以节点是否被选中或曲线包围盒代替。可以只框到线中间，也可以混选节点和连线。
- 原先单个节点／连线的属性面板状态会覆盖多选，删除也分成两次处理。现在以画布选中集合为准，节点、连线及节点关联线作为一次删除提交；只选多个节点时同样完整删除。剧情开始节点不能删除。
- 节点参数支持单独与整图折叠，保留连接点与端口名称，尺寸变化后更新接线位置。折叠状态按工程保存在本机，不加入作品文件或撤销记录。

## 同机开发模式对照

脚本：`scripts/verify-blueprint-performance.ts`。从哀鸿模板创建独立副本，加入“限时点亮”示例；共 12 张蓝图、259 项素材、182 个 UI 组件。测量的蓝图包含 52 个节点和 56 条连线，参数全部展开，右侧属性栏显示。

| 操作 | 修改前总耗时 | 修改后总耗时 | 修改前／后超过 50ms 的任务数 |
| --- | ---: | ---: | ---: |
| 连续点选 10 个节点 | 3241.7 ms | 724.1 ms | 21 / 0 |
| 80 步拖动并松手 | 3595.1 ms | 1503.6 ms | 11 / 1 |
| 80 步平移 | 1378.6 ms | 1392.1 ms | 0 / 0 |
| 连续缩放 | 1324.3 ms | 1218.6 ms | 1 / 0 |
| 依次输入 1、12、123、-2.75 | 1757.0 ms | 465.6 ms | 8 / 4 |

点选总耗时减少约 78%，参数输入减少约 74%，拖动减少约 58%。这是包含自动输入、帧等待与开发模式开销的场景对照；平移基本持平。参数修改仍会同步文本、历史和诊断，不能解释为所有操作都没有主线程停顿。

拖动的帧间隔 P95 由 33.3ms 降至 16.8ms；参数阶段由 516.7ms 降至 100ms。缩放 P95 本次为 33.3ms，基线为 16.8ms，未取得改善。帧序列覆盖 CPU Profiler 的启停开销，尤其首阶段最大帧包含额外暂停，因此主要比较操作总耗时和长任务，同时保留原始记录。
