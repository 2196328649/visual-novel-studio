# 2026-11-12 编辑器体验检查与修复

本轮接续玩家剧情图属性面板和字间距工作，按用户的“持续优化编辑器，修复 bug，作为用户体验编辑器”目标，实际操作编辑器后修复确定的问题。全部产品改动完成后统一单测、编译、桌面验收。没有修改真实作品、提交、打包或更新安装版。

## 已修复

### 窄属性栏中的数值被遮住

220px 属性栏中，原来的宽度输入实际值为 `1024`，画面只能看见 `1`。输入框只有76.5px，左右装饰占去54px，尚未计入数字微调按钮。

现在位置与尺寸根据可用空间排一列或两列，保留外部中文名称，将 `%`／`px` 单位放在输入框旁。220、280、360px 和明暗主题均检查了负数、小数、0、1024、4096；数字可完整读取。没有扩大面板的最小宽度。

实现：`UiInspector.tsx`、`ui-inspector.css`。

### 参数搜索、详情和键盘操作对象不同步

原来已选“可调整数值”后搜索“玩家姓名”，列表只剩“玩家姓名”，右侧却仍编辑旧参数。从总览按成员名搜索后进入分组，也会丢失搜索并选择首项。通过 Tab 移动焦点再按 Delete，可能操作之前选中的对象；删除后键盘焦点可能落到 BODY。

现在列表高亮、右侧详情和快捷键共同使用当前可见结果。搜索没有结果时显示明确空状态，清除搜索可恢复列表。内置偏好也能从总览搜索；改名变得不匹配时清除查询并保持当前输入，避免输入框突然卸载。

搜索的具体规则：按分组名进入显示整个分组并清空查询；按成员名进入保留查询并选中命中项；返回总览保留当前查询。没有额外维护第二套总览搜索词。

参数行获得键盘焦点时同步选中。删除后优先聚焦下一条可见行，其次上一条、内置设置，最后新增按钮；取消删除返回原焦点。删除最后一个搜索结果后仍保留查询，撤销可恢复结果。撤销不主动从工具栏抢回行焦点，F2／Delete 仍只在参数行或工作区获得焦点时处理。

实现：`ParameterSets.tsx`、`ParameterChangeDialog.tsx`、`ParameterDetails.tsx`、`PreferenceDetails.tsx`。

### 切回界面时画布和属性属于不同页面

原来在存档页选择存档槽，经参数集返回界面后，画布回到标题页，属性栏仍显示存档槽，存在误改其他页面对象的风险。

现在从有效选中组件恢复页面、自定义页面和存读档模式。显式诊断／参数定位仍可覆盖此选择；用户手动选择后会清除过时定位请求。属性栏只接受当前页面中的组件，提交前再次校验对象、类型、页面和界面方案；失效回调不能创建错误的继承覆盖。

新增核心测试覆盖有效方案、自定义页面、读档模式、缺失及停用组件。桌面验收覆盖“参数定位到设置页 → 手动选存档槽 → 切到参数集 → 返回界面”，并核对页面、层级选中、画布和属性一致。

实现：`ui-page-authoring.ts`、`UiEditor.tsx`、`UiInspector.tsx`、`App.tsx`。

### 素材搜索弹层没有跟随输入框

原来属性栏滚动后，输入框从约559px移到799px，搜索结果仍停在约594px。现在弹层以实际输入框为锚点，随祖先滚动、面板尺寸和视口变化重新定位；输入框完全离开可见范围时关闭。弹层自身滚动不会选择资源或关闭。

中文输入合成期间，Enter、上下键和 Escape 不触发素材提交、换选或关闭；集合编辑窗口也避免预先拦截合成中的 Escape。结束合成后正常键盘选择恢复。已用合成事件验证事件处理语义，**没有自动操作 Windows 原生输入法，不将此表述为操作系统 IME 全面验收**。

实现：`AssetPicker.tsx`、`UiCollectionContentDialog.tsx`。

### 整篇剧本序列化中的重复扫描

`projectToText` 原来按章节、场景和节点反复扫描整份数组，并重复查找名字。改为单次调用内的有序分组和索引，保留原数组顺序、重复 ID 首项优先、缺失引用回退和输出文本。没有延迟同步或引入跨调用缓存，撤销与保存规则不变。

新增3项测试覆盖交错数组顺序、重复／缺失引用和文本往返。专用对照脚本在内存中替换本轮修改前的函数片段，比较相同输入，每个版本16次、ABBA顺序：

| 输入 | 修改前中位 | 修改后中位 | 文本输出 |
| --- | ---: | ---: | --- |
| 真实作品，240句 | 9.77ms | 9.42ms | 完全一致 |
| 内置模板，73句 | 3.24ms | 3.31ms | 完全一致 |
| 合成大工程，4000模块／12000句 | 303.35ms | 58.26ms | 完全一致 |

这是序列化函数的数据，不代表整次输入或整个编辑器同等提速。真实作品在这个环节改善很小，模板差异处于波动范围。复杂演出辅助函数和其他渲染路径仍有查找成本。

实现：`text-script.ts`；基线保留在 `artifacts/editor-ux-2026-11-12/serialization-baseline.ts.txt`。体验阶段的 `serialization-source-during-implementation.txt` 已包含实现中的代码，**不是旧版本基线**。

## 性能仍有的限制

真实作品隔离副本采样为240句、469素材、20角色，约14988个DOM节点。本轮只测最终实现，没有同轮完整界面旧版对照：

| 操作 | 输入到下一帧中位 | p95 | 观察 |
| --- | ---: | ---: | --- |
| 首次切换选中行 | 99.3ms | 单样本 | 64／104ms长任务，自动滚动18ms |
| 首次展开文字演出 | 37.8ms | 单样本 | 无超过50ms长任务 |
| 连续输入12次 | 29.4ms | 42.4ms | 无超过50ms长任务 |
| 后续切换选中行5次 | 25.9ms | 47.7ms | 仍有94／53ms长任务 |
| 反复展开6次 | 15.8ms | 18.9ms | 无超过50ms长任务 |
| 连续调整数值6次 | 58.5ms | 71.1ms | 55～70ms长任务 |

采样包含自动化定位、浏览器布局与GC开销，不能仅从压缩函数名断定全部原因；保留7份CPU profile供继续分析。首次选中和连续数值调整仍可感到停顿，不宣称“全部不卡”。后续优先考虑减少选行时的同步布局及大型模块视图的重复渲染，不在本轮末尾未经重新验证地扩大改动。
