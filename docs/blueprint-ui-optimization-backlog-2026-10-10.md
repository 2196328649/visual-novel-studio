## 1. 优化目标

让创作者能够完成并理解以下工作：

1. 打开任意蓝图，都能知道它属于哪个页面、界面方案或调用流程，以及何时执行。
2. 用基础逻辑节点表达条件，不必为 NOT 这样的简单运算拼出难读的替代流程。
3. 在蓝图中读取和修改常见控件内容，例如切换图片、改变文字颜色；复杂列表页码等接口扩展随 WG 项目暂缓。
4. 新建页面后，能直接把它接入剧情、标题按钮、新游戏流程或标题前流程。
5. 候选目标（暂缓）：能修改图鉴、存档列表等复合控件的外观、条目结构和交互，同时保留已有数据与运行规则。
6. 通过预览和调试知道事件是否触发、值从哪里来，以及为什么没有得到预期结果。

普通蓝图与 UI 蓝图区分用途、归属和生命周期，共享图编辑器、连线、参数、复用模块与编译基础。优先补齐视觉小说和界面制作的高频能力，UE 的节点与组件设计可作为交互参考。

## 2. 实施前核查（历史基线）

本节保留开工前的现状与缺口，用于追溯优化依据；不能据此认定已接通的能力仍然缺失。最新实现状态和测试证据以实施记录及下方勾选项为准。

| 范围 | 当前支持 | 缺口或问题 |
| --- | --- | --- |
| UI 蓝图归属 | 数据已有 UI 类型、所属页面、界面方案；界面编辑器有专用事件图环境 | 从资源管理器打开同一图会进入普通演出工作区，缺少控件树与页面事件工具；已用隔离工程复现 |
| 节点库筛选 | UI 环境有“仅界面相关” | 主要按中文类别筛选，无法准确表达运行要求；例如保留“结束小游戏”，却排除“播放音乐” |
| 基础逻辑 | 已有分支、比较、选择值、数学运算、计数循环、依次执行、等待 | 当前节点目录没有独立的 NOT、AND、OR、XOR 节点 |
| 蓝图复用 | 已有可复用流程、用户节点、输入输出、类型化连线；文本演出可封装为蓝图 | 需要加强画布内所选节点封装、模块接口说明及修改影响展示 |
| 控件运行时属性 | 通用属性目录共 10 项：显示、启用、选中、文字、横纵位置、宽高、不透明度、进度；具体控件只支持其中适用项 | 没有图片素材、图片缩放方式、字体颜色等大量设计侧属性的蓝图读写接口 |
| 控件事件与动画 | 已有点击、悬停、按下/释放、值改变、文字提交、按键、定时；已有控件动画及 Spine 播放、暂停、速度控制 | 需要继续补齐能力、声明适用范围和生命周期，不能把已有功能重复列为新增 |
| 自定义页面 | 可新建页面；已有打开、等待关闭、叠加显示、关闭结果；预览支持相应交互 | 新页面没有清晰的“用在哪里”入口与使用位置列表；页面入口和内部事件的概念混在一起 |
| 标题前流程 | 工程有“故事入口”，它在玩家开始新游戏时执行 | 当前核查未发现标题前启动流程的专用配置、可视入口或对应生成逻辑；故事入口不能替代它 |
| 图鉴配置 | 已能编辑分组、分镜、缩略图、解锁条件、网格、分页皮肤和部分详情行为 | 条目内部控件与详情界面由运行时代码生成，不能直接作为普通控件树编辑；缺少公开的条目事件接口 |
| 控件组合 | 已有父子层级、子树复制、界面方案继承 | 尚未提供通用的条目模板、详情模板与可复用控件定义；这些不同于现有页面方案继承 |
| 复杂控件放置 | 图鉴、存档列表等支持对应的内置页面 | 多种控件与固定页面类型绑定，不能直接任意放到新建自定义页面；需要连同运行上下文一起改造 |
| 预览与性能 | 已有独立界面预览、节点参数折叠、错误定位、自动排列等 | 尚无完整蓝图断点调试；蓝图编辑路径仍有全工程复制、序列化和全量签名同步 |

特别注意：新建自定义页面目前会生成一张类型为 UI、但没有显式页面归属的混合图，内含“调用时打开页面”和“关闭按钮被点击时关闭页面”。不能只根据 UI 类型给旧图补上所属页面，否则可能把原来的调用入口变成页面显示事件，形成重复打开或递归。

### 4.2 BP-02：补齐基础逻辑

| 批次 | 节点/能力 | 目标行为 |
| --- | --- | --- |
| 首批 P1 | NOT / 取反 | 一个开关输入、一个开关输出，无执行引脚；真变假、假变真；本身不修改状态 |
| 首批 P1 | AND / 全部满足；OR / 任一满足 | 先支持两个开关输入；多输入扩展保留稳定引脚 ID；明确并统一从左到右的短路求值规则 |
| 后续 P2 | XOR / 不同；多路选择与枚举分支 | 减少多层条件分支；错误类型不能悄悄转换成真假 |
| 后续 P2 | Clamp、绝对值、取整、范围判断、近似相等、数值映射/插值 | 用于进度、位置、音量和动画；已有加减乘除、取余、最小/最大值继续复用 |
| P2 分批 | Do Once、Gate、防重复点击、节流、防抖、可取消任务 | 已完成 Do Once/Gate 的调用和页面实例状态、有限重置回线与工作期间防重；节流、防抖及独立可取消任务的源码与待执行用例已接通，尚未统一验收。已有等待、定时和动画停止能力保留 |
| 后续 P2/P3 | 列表、记录、按键查值、遍历条目 | 按未暂缓的实际使用场景扩展通用数据类型；用于复合控件重构的部分随 WG 项目暂缓；不要求创作者手写 JSON |

历史临时接法（NOT 尚未实现时）：使用“比较”节点，将比较类型设为开关，判断输入是否等于“否”，可以得到 NOT 的结果。当前已有独立 NOT；分支的“不满足”出口仍只改变执行路线，不等于提供一个可继续连线的取反值。

目标示例：读取“说明图片”的显示状态 → NOT → 设置“说明图片”的显示状态。读取和计算是数据流，点击事件到设置节点的白线负责执行。

2026-10-14：另已修订任务空体循环的逐轮合作检查点、完成索引及失败/全局预演停止区分，补写共享夹具和原生边界入口，仍未验收。

2026-10-14：数值运算与多路选择/分支的源码、作者字段及三层待执行用例已补齐；新增增量编辑的 50/200/500 节点同源性能矩阵，并接通节流、防抖、独立任务的统一调用/页面生命周期、预演与原生合作式调度。上述新增实现尚未统一编译或验收，不以源码存在或历史绿灯认定完成，见[续接记录](blueprint-ui-implementation-2026-10-10.md)。

## 5. 控件属性、操作与事件

- [ ] 默认“获取属性”返回当前页面实例的有效运行值；“获取设计默认值”单独表达，避免与蓝图覆盖后的值混淆。

## 6. 新页面怎样接入游戏

### 6.1 当前可用的操作

以下入口已接通；完整验收范围与尚待补齐的边界见实施记录。

1. 在“界面”中新建自定义页面，生成标题、关闭按钮与独立的页面内部事件图，并自动打开“接入游戏”向导。
2. 在向导中选择剧情位置、已有按钮、启动到标题之间或新游戏到故事之间，也可保留为备用资源。保存界面后，可定位到同一流程蓝图中的页面节点。
3. 外部调用图与页面内部事件图分离。原有文本 @调用名称、蓝图“调用流程”和“打开自定义界面”仍兼容；旧混合图不被自动改写为页面显示事件。
4. 需要玩家操作完再继续剧情时，将“等待关闭”设为是。页面中的按钮执行“关闭自定义界面”，返回结果交给调用流程判断；当前关闭结果是文字。
5. 需要从标题或暂停菜单进入时，为按钮设置“调用蓝图”，或在按钮点击事件中连接“打开自定义界面”。应能看清现有绑定，防止同一次点击重复打开。

把页面放到故事入口，只能让它出现在开始新游戏后的剧情阶段。标题显示之前需要独立的游戏启动入口。

### 7.2 WG-02：条目与详情成为可编辑模板（暂缓）

目标分为三层：

| 层级 | 用户怎样编辑 | 适用情况 |
| --- | --- | --- |
| 基础配置 | 修改数据、尺寸、颜色、皮肤与现有行为选项 | 快速使用内置图鉴/存档等组件 |
| 条目和详情模板 | 点击“编辑条目模板”或“编辑详情模板”，进入普通控件树，修改图片、文字、锁标、按钮和布局 | 保留列表/解锁功能，重新设计视觉结构与交互 |
| 自定义复合控件 | 从模板创建自己的组件，公开属性、插槽、操作和事件；可在多个页面复用 | 自定义图鉴、背包、任务列表和角色卡片等 |

模板内部应能选中实际组成部分。例如图鉴条目包含缩略图、标题、锁定标记和自定义角标；详情模板包含遮罩、大图、说明、前后切换和关闭按钮。每个重复条目是模板实例，不把整个图鉴展开为数千个独立设计对象。

- [ ] 图鉴提供有类型的数据上下文：稳定分组 ID、名称、缩略图、分镜、解锁状态、当前项/页码等。先暴露确定字段，再扩展通用列表数据。
- [ ] 公开条目点击、尝试打开锁定项、页码变化、详情打开/关闭、分镜变化事件；操作提供翻页、定位、打开详情和关闭详情。
- [ ] 事件配置区分“保留默认行为并附加逻辑”和“替换默认行为”。默认打开详情与作者自定义打开动作不会重复执行。
- [ ] 数据与视图分离：解锁、存档读写、收藏等继续走原有服务；自定义模板通过公开接口使用，不能因换皮肤绕过解锁或破坏存档。
- [ ] 提供“编辑组件定义”“仅修改此实例”“恢复默认”；显示修改影响哪些页面，并保留已有实例覆盖。
- [ ] 普通父子层级、页面方案继承继续保留；新控件定义具有自己的内部控件树、公开参数、具名插槽及事件图。
- [ ] 按能力逐步放开固定页面限制。例如图鉴数据与浏览可用于自定义页面；存读档等操作仍声明所需游戏状态，不能只删除页面校验。
- [ ] 使用稳定条目 ID 维持选择、焦点和局部状态；筛选、分页、重排后不把状态错误转移到其他条目。

图鉴可作为第一种改造对象，再复用到存档格、音乐列表、语音收藏、历史列表、章节列表和选项列表。不同控件保留专属行为契约，避免将它们强行压成只会显示图片和文字的通用列表。

## 10. 验收场景与迁移约束

以下均为未来实施的验收要求，不是本轮已通过的测试。A10～A12 随开放复杂控件暂缓，不阻塞其余项目完成；已有复杂控件仍需做必要的兼容性回归。

| 场景 | 通过条件 |
| --- | --- |
| A01 同图多入口 | 资源、控件事件、搜索和诊断进入同一页面/方案，控件库、参数、保存和撤销范围一致 |
| A02 旧混合图 | 旧自定义页面调用仍只打开一次，关闭仍返回原调用；迁移不会把打开入口变成递归的页面显示事件 |
| A03 逻辑节点 | NOT 真/假、AND/OR 全组合及短路行为正确；错误类型有诊断；预览与实际游戏一致 |
| A04 图片切换 | 按钮切换两张不同尺寸图片，获取值正确，缩放模式正确；清空/缺失图片有明确效果；蓝图独占引用的素材能导出 |
| A05 属性与绑定 | 修改、读取、重置、参数绑定、方案继承和动画替换遵循规则；设计数据及预览外的玩家数据不受污染 |
| A06 剧情接入 | 新建页面接入指定剧情位置；等待关闭、叠加显示和返回结果分别正确；取消后执行确定分支 |
| A07 标题前流程 | 冷启动先显示指定页面再到标题；返回标题是否重播符合配置；无配置的旧工程保持原流程 |
| A08 新游戏与读档 | 新游戏前流程只在正确时机执行；读档不重做角色创建、不重置存档值；首次标记与预览隔离 |
| A09 页面生命周期 | 重复打开、嵌套模态、关闭/取消、返回标题后不留下重复事件、定时任务或悬空等待，焦点正确恢复 |
| A10 图鉴模板（暂缓） | 改条目文字/角标/锁标及详情按钮布局后，分页、解锁、分镜顺序、关闭返回和焦点恢复仍正确 |
| A11 自定义交互（暂缓） | 为条目添加逻辑或替换默认详情行为只执行一次；未解锁内容不会因换模板暴露 |
| A12 组件复用（暂缓） | 模板修改与实例覆盖各自生效；复制、重排、删项后事件仍指向正确控件与稳定条目 ID |
| A13 兼容与持久化 | 旧工程打开、保存重开、撤销重做、派生方案、资源改名/删除、游戏存读档与回滚按已定义语义工作 |
| A14 可读性与诊断 | 常见窗口尺寸下核心操作不溢出；缺失控件、错误能力与不支持的预览功能能定位并说明原因 |
| A15 性能 | 使用相同工程对比基线；局部编辑不触发无关全图重建；已有列表性能保持稳定。新增模板的性能验收随 WG 项目暂缓 |
