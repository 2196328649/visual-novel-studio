# 剧本文本输入响应优化（2026-10-04）

《琼.第一回：归（崇祯五年）》首轮优化后，连续输入仍会触发从故事入口到当前对白的舞台推演。一次渲染还会分别计算当前演出、完整演出及编辑状态；实际工程中这些计算造成每个字符后约 110–150 ms 的主线程长任务。

本轮修改：

- 预览窗口复用纯对白文字修改之前的舞台计算；对白内容始终取当前工程，因此文字即时更新。
- 任何演出、发言角色、场景、分支、蓝图、参数或其他工程字段变化均使缓存失效。不同对白、路径和指令位置分别计算；缓存最多保留四份舞台结果。
- 完整演出结果在静态预览、编辑舞台和播放计划之间共用，避免重复推演。
- 剧本编辑器和目录共用当前文本的解析结果。撤回首轮中对目录解析的 `useDeferredValue`：隐藏 ID、隐藏演出和换行映射需要与正在编辑的文本同步。

## 工程副本实测

测试使用原工程 JSON 的独立副本及独立桌面配置，素材通过外部引用读取，原工程 SHA-256 前后相同。工程包含 20,412 字符、230 句对白、789 项素材和 14 张蓝图。两种模式各连续输入 24 个字符，使用相同本地编译界面、30 ms 按键间隔及性能采样方式。

| 模式 | 输入到下一帧 P95：优化前 → 后 | 最慢输入帧：优化前 → 后 | 超过 50 ms 的主线程任务数：优化前 → 后 |
| --- | --- | --- | --- |
| 显示演出 | 13.9 → 29.9 ms | 41.6 → 36.3 ms | 24 → 0 |
| 隐藏演出 | 24.9 → 39.1 ms | 269.5 → 40.1 ms | 26 → 0 |

此前延后解析会较早显示一帧，但随后仍持续阻塞主线程。本轮使用同步文本映射，首帧 P95 略增加，同时消除了这两组连续输入中的长任务。结果是本机有限样本，不代表任意大小工程的性能保证。
