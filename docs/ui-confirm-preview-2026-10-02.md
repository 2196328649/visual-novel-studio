# 高级 UI 确认框与蓝图菜单预演（2026-10-02）

确认框和蓝图标准菜单调用已接入高级 UI 参数预演。整体目标未完成：标准菜单内置控件、其他集合、小游戏上下文和声音/演出协同仍有未覆盖范围；原作核对限制不变。

## 行为

共享解释器在 `confirmMessage` 等待响应，只执行确认或取消的一条路线；动态提示按文字显示，不解释 `[name]` 和 `{b}`。使用当前方案的自定义消息框；没有自定义布局时显示标准确认框，并且不执行作者消息框组件的事件。自定义提示按空间缩字，仍放不下时滚动；标准框的长提示滚动，按钮始终留在预演区域内。

点击回调打开第二个确认框时，先完成内层回调再执行原按钮响应。每次请求有独立标识，过期响应不会接受新请求。Escape和右键取消；关闭恢复调用按钮焦点，恢复测试值取消全部临时等待。确认框显示期间底层页面计时继续。

`uiAction` 打开设置等标准菜单时保留蓝图执行位置。菜单内导航保留本次调用，返回后恢复真正的调用页面（包括等待中的自定义页）并继续蓝图。菜单隐藏底层页面并暂停其计时，关闭后从原计时位置继续。音量测试值在导航后保留。角色音量的返回按钮、Escape和右键先回设置，再返回调用者。标准布局的内置菜单控件仍需试玩检查；预演提示保留，Escape可结束本次菜单等待。

静态演出预览遇到确认框或菜单等待会停止并标记不完整，不提前执行后续路线。这些测试只改变临时状态，不保存工程或玩家数据。

## 原生运行时修复

同夹具Ren’Py验收发现：从标题经蓝图打开设置后，原有普通返回动作只显示标题，蓝图调用仍停在新上下文的菜单交互中。仅换成 `Return()` 也不足以修复，因为引擎在 `main_menu=True` 时仍会显示标题。

生成器增加菜单调用包装入口和 `vn_bp_menu_active` 上下文变量，使用 `renpy.context_dynamic` 在退出时恢复。包装入口仍调用引擎 `_game_menu`，保留进入菜单逻辑；作者返回按钮、公共菜单返回按钮和 `game_menu` 快捷键在该调用中跳到专用返回标签，播放退出声音/转场后退出当前调用。原有 `main_menu` 状态保留，因此标题下仍禁止保存游戏。角色音量仍先返回设置，普通标题导航及明确返回标题动作保持原语义。没有修改 SDK 的 common 文件。
