# 控件值改变事件 · 2026-10-03

按用户要求继续完善控件事件图。滑块、参数开关、选项和文字输入现在可以从当前控件直接添加“值改变时 · OnValueChanged”，使用新值和旧值数据引脚驱动界面行为，无需用计时器轮询参数。

## 使用方式

1. 在“界面 → 设计”中选择已绑定参数或玩家选项的设置控件。
2. 切换到“事件图”，选中左侧控件，添加“值改变时 · OnValueChanged”。重复添加会定位已有入口。
3. 白色执行引脚决定执行顺序；“新值”和“旧值”引脚提供本次改变的数据。例如音量的新值连到进度条，开关的新值连到文字的“显示”，文字输入的新值通过格式化节点更新说明。
4. “交互预演”中可以实际拖动、键盘调节、切换和输入。保存界面后写入工程；撤销重做、保存重开和退出放弃仍适用。

## 事件约定

- 节点类型为 `eventValueChanged`。属性为 `componentId` 和 `uiInstanceId`；`exec` 是执行输出，`value` 是新值，`previous` 是旧值。数据引脚跟随实际绑定的 `number / boolean / string`，切换到其他方案时保留未显示控件的声明类型。
- 支持 `preference`、`preferenceChoice` 控件，绑定作品参数或玩家选项。原有控件页面放置规则保持生效；不凭空增加新的控件种类。
- 先写入设置，再执行事件。连续选择相同值不触发；初始化、界面重建、直接设置变量/玩家选项及预演测试参数不会主动广播控件事件。
- 事件中的新旧值是输入快照。回调随后修改参数不会改变这两个输出；原生通过标签局部参数传递，预演通过独立解释器调用传递。
- “启用”属性扩展到设置控件。隐藏、禁用或被上层模态页面覆盖时不接受用户输入。叠加页面按实际顺序判断，底层模态页不会禁用上层的控件。
- AI 提示同步真实节点属性、输出引脚和触发约定。本轮没有调用真实外部模型，不据此声称 AI 生成能力全覆盖。

## 原生交互修复

值改变回调沿用蓝图的新上下文执行方式。Ren’Py 返回父上下文时会清空焦点，导致正在拖动的滑块虽然仍持有抓取，却不再接收松开事件。现使用 `VnUiBar` 保持同一控件替换期间的抓取，并让抓取者接收后续移动与松开；源控件和源页面仍可用时恢复输入焦点。隐藏、禁用、离页或打开模态页会清理抓取，读档恢复阶段也清理。

设置控件的原生子控件 ID 现在使用组件身份。两个控件可以绑定同一参数，分别位于底层页面和弹窗；事件仍只归属实际操作的控件。没有摆放到界面中的通用参数设置保留原参数 ID。旧 `verify-authoring-runtime.ts` 的三个控件定位已同步新 ID，本轮没有重跑该脚本的历史演出部分。

选择器默认箭头改为字体普遍支持的 ASCII 字符，避免内置精简字体将原箭头显示为缺字框；自定义箭头图片继续使用原素材。

## 范围与限制

这是用户操作事件，不是通用参数观察器。蓝图中直接修改参数后，其他控件会显示该值，但不会再触发一轮 OnValueChanged。当前同一事件入口沿用已有重入保护：若该入口正在等待交互，重复进入会被忽略；持续输入处理应优先使用不等待的控制或动画节点。预演仍受既有 256 条输入记录和时间范围限制。

输入完成/失焦提交、焦点与拖放事件、动画循环/倒放等尚未完成；不等同完整 UMG。原作还原、旧入口迁移、剧情流程全选删除和 AI 全覆盖等总体待办不变，整体 goal 保持 active。
