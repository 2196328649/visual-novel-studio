## 需要与用户商量的逻辑

1. **整句时长与停顿冲突。** 例如整句设为 1 秒，句中停顿设为 2 秒，两者不能同时满足。当前预览以整句时长结束，游戏按停顿继续等待，存在不一致。建议保留作者明确设置的停顿，让总时长顺延，并在面板显示实际时长和冲突原因；另一种方案是按总时长同比压缩停顿。此轮不替用户改变创作规则。局部入场时间较长、出现顺序不同时的完整计时也应一起处理。
2. **局部粗体与斜体是否允许显式关闭。** 当前局部只有“开启／继承”，因此整句粗体中的几个字不能恢复正常字重。可改为“继承／开启／关闭”，需要同时扩展工程字段、文本写法和游戏编译规则。
3. **按职责逐步拆组件。** `App.tsx` 集中保存、预览、导入、导航与 AI；`Inspector.tsx` 集中多类资源编辑。真正的风险是多入口重复更新规则，不是单纯文件行数。建议先拆项目保存事务，再整理媒体生命周期与文字样式的共享规则；不进行整文件搬家式重构。

## 剩余性能开销

真实工程只读副本仍是 227 行长段落、341 素材、20 角色。本轮没有再修改列表布局。收起首次、展开首次、展开稳态、六行展开与带动画滚动各采样 72 次滚轮事件，记录中没有超过 50ms 的长任务；展开首次滚动帧间隔 p95 为 12.1ms，带动画滚动 p95 为 23.8ms、最大 28.9ms。离屏小预览样式变更为 0，返回后继续。

首次点击选行仍有约 124.6ms 的鼠标处理，其中一次强制布局约 62.2ms；该阶段没有新增字体解码。它发生在开始连续滚动采样之前，不能用“滚动无长任务”来描述所有操作都不卡。后续可针对选行后的自动定位与同步布局继续剖析，再决定是否改交互；本轮仅记录，没有通过取消自动定位来掩盖开销。

1500 句文本用例的输入到下一帧中位数为 49.8ms，暂停预览后为 42.4ms；这是本机本次采样，并非适用于所有工程的保证。
