# 界面功能组件与流程连线过渡：设计提案

日期：2026-11-09。状态：**只读调查后的待讨论方案，未实施产品改动**。

后续状态：用户已选择先实施剧情连线过渡，该部分的当前范围和验收见 [剧情连线过渡](flow-transitions-2026-11-09.md)。控件组件化仍处于研究阶段，补充建议见 [组件式属性补充设计](ui-components-further-design-2026-11-09.md)。本文保留最初提案，下文“未实施”仅描述提案形成时的状态。

本轮结合当前 AGENTS、交接文档及三项子代理审查，分析属性面板、参数／蓝图／动画、控件继承，以及剧情、页面与演出的执行路径。以下“建议”均为目标设计，不代表当前产品已经支持。没有运行产品编译、单测或桌面／游戏验收。

## 1. 推荐方向

界面采用“控件对象 + 功能组件 + 可复用控件模板”。保留作者熟悉的一键创建按钮、文字、滑条、存档列表；上方仍是所有对象共有的属性，下方显示对象实际拥有的功能。

流程图采用“真实执行出口上的视觉过渡”。作者从连线编辑这次衔接，底层仍由原剧情／页面导航执行。剧情组保持组织用途，打组不增加运行边界。

两项工作共用属性描述、动画预设与生命周期约定，但分别保留各自的数据归属。页面开关、剧情导航、控件动画不合并成一个无所不包的组件。

## 2. 当前基础和真实问题

已完成并应保留：通用／功能分层、子对象归通用区、添加子对象保持父选择、字段同行、搜索和折叠记忆、内部部件独立作用域、属性右键默认／单向跟随／双向同步、完整框选。

尚需解决的结构问题：

| 当前事实 | 影响 |
| --- | --- |
| `UiComponent` 是 23 种固定 `kind` 共用的大对象 | 整理折叠面板不等于可以自由添加能力 |
| 正文、字体、效果分别属于内容、外观等组 | 完成一个任务需跨组找字段 |
| 内容、外观、事件、搜索各有类型判断 | 新增一种能力需要多处同步，容易漏支持 |
| 设置控件由绑定参数推导值类型和部分输入形态 | 选择数据来源可能影响控件功能，缺少独立的输入契约 |
| 普通子对象与集合内部部件是不同结构 | 新增一个子文字不会自动在所有存档条目中重复 |
| 界面方案当前按整控件覆盖 | 不能当作 Unity 式逐字段模板继承 |
| 预览与游戏分别由 TypeScript 和生成的 Python 实现 | 注册表可以统一契约，但新增功能仍需两端实际支持 |

主要依据：`src/core/model.ts`、`src/core/ui-properties.ts`、`src/core/ui-control-properties.ts`、`src/core/ui-inspector-search.ts`、`src/renderer/UiInspector.tsx`。

## 3. 对象与功能组件

### 3.1 四类内容

| 层次 | 作者看到的内容 | 约束 |
| --- | --- | --- |
| 固有通用属性 | 名称、位置大小、父级与层级、变换、显示、子对象 | 每个控件都有，无需手动安装基础组件 |
| 内容与输入功能 | 文字、图片、视频、Spine、点击、滑条、开关、文本输入 | 按实际组合能力开放；不因换参数隐式更换类型 |
| 可选增强 | 自动排列、裁切滚动、文字效果、状态外观、声音反馈、提示、快捷键、动画 | 声明依赖和互斥；仅支持真正可用的启用／移除 |
| 业务功能 | 存档、历史、图鉴、玩家剧情图等 | 保留专用数据和操作语义，先封装再推广为通用结构 |

子对象属于所有控件。对子对象的排列／裁切可作为按需启用的通用能力，显示在上方通用区；系统列表的条目排列留在列表功能中，标签说明作用范围。

首期支持既有的文字、图片、点击等合法组合。同类的多份独立文字或图片仍优先使用子对象，避免立即引入多个同类渲染组件、叠放顺序及引用歧义。后续真正开放多实例时，必须有稳定的功能实例 ID。

### 3.2 属性归属按完整任务划分

- 文字：正文／系统文字角色、字体、字号、颜色、对齐、描边和阴影。
- 图片：素材、显示方式、九宫格、图片效果。
- 点击：动作、允许交互条件、点击事件、定位原蓝图。
- 状态外观：仅保存相对普通态的差异，不复制一份普通态基础值。
- 滑条／开关／输入：输入类型、当前值、范围／选项、玩家改值事件。
- 列表：业务内容、条目排列、条目模板、分页和操作。

用户入口称“添加功能”，整块右栏称“控件属性”，避免“组件”同时指整个控件和其中的功能。组件卡片只是显示方式；只有实现了实际组合、保存、运行与移除能力后才开放对应添加按钮。

### 3.3 三个例子

**图文按钮**：文字、图片、点击、状态外观、声音反馈。保留现有按钮标题的快捷输入；复杂图标、不同字体段落可以使用子对象模板，不强迫简单按钮拆成多个对象。

**音量滑条**：明确“数值输入／滑条”“范围”“当前值来源”“轨道与滑块”“改值事件”。输入形态和值类型独立于参数选择；参数不兼容时提示，不自动变成别的控件。

**存档列表**：先保留存档业务组件，下挂“条目排列”“条目模板”“翻页”。条目模板入口明确写“修改影响所有槽位的外观”，进入后显示路径并可返回。普通子对象只属于整个列表。

## 4. 面板交互

- 组件收起时显示一行有效摘要，例如“返回上一界面”“跟随：角色名称”；关联后不继续用失效的保留默认值充当摘要。
- 常用字段与名称同行；字号、时长等短字段可并排；高级设置最多再展开一层。
- 没有实际内容的组件不展示。缺失引用等错误在标题上可见，并可定位。
- 折叠只影响面板；停用影响功能，保留配置。不能给每张卡强加一个无语义的开关。
- 菜单区分复制设置、重置本功能、停用、移除、还原模板覆盖。每项操作使用精确的字段归属。
- 添加功能按依赖一次完成、一次撤销。移除前检查蓝图、参数关联、动画和模板公开字段，不静默清理其他资源。
- 组件卡片的排列首先只是编辑顺序，不自动决定绘制层级或事件执行顺序。
- 复杂内容使用“编辑内部结构”明确入口及范围说明，双击只是快捷方式。
- 框选后逐步支持共同属性批量编辑；不同值显示混合状态，提交前整体校验。存在受控属性时明确指出，不能悄悄只改一部分。

## 5. 属性控制继续共用一套机制

保留属性名称右键与已关联字段的点击入口：

1. 默认：保留设计／系统来源及原蓝图、动画规则。
2. 单向跟随：只限制这一项属性的直接写入。
3. 双向同步：主动输入、蓝图与动画的有效写入先进入参数，再传播显示。

来源是跨组件的属性机制，不再新增接管整个控件的“数据绑定组件”。参数传播不伪造用户事件，同一参数只有一个有效动画驱动，解除关联恢复原来源。现有素材类型等能力边界仍按真实实现开放。

要区分静态可编辑、蓝图可写、可绑定和可动画；不能因为某字段出现在通用组件里，就声称四项都支持。

模板的“公开字段”也不等于项目全局参数。标题、图标、点击动作等用于配置每个模板实例；只有作者显式关联，才连接游戏或玩家参数。

## 6. 架构与扩展契约

扩充现有 `uiProperties`，建立功能注册信息：稳定 ID、适用能力、依赖／互斥、单例或多实例、属性归属、搜索词、默认值、校验、设计编辑器、运行读写、事件、动画与释放。

注册表引用一份属性定义，不再复制类型、范围、来源规则和重置范围。复杂编辑器可定制，但仍通过统一设计命令写草稿，保留撤销和作用域保护。

分阶段存储：

1. 兼容适配现有 `kind` 与字段，保持旧控件／属性 ID；先建立统一归属。
2. 对真正新增的可组合能力设计有版本的容器及稳定实例身份。未知功能保留其数据并显示缺失提示，不假装能够运行，也不在保存时剥离。
3. 未来多实例属性引用定位“控件对象 + 功能实例 + 属性”；旧引用可映射到默认实例。

外部扩展还必须提供编辑预览和 Ren'Py 运行支持。首期不开放任意脚本插件加载器，不以“能插一张表单”冒充完整扩展体系。

性能设计：按功能按需挂载复杂面板，搜索来自描述信息，参数按依赖通知；不为每个组件新增定时轮询。折叠／屏外只暂停编辑器的小预览，不改变游戏行为。组件化本身不保证提速，需要后续统一验收采样。

## 7. 模板复用

建议先用“图文按钮”和“设置行”验证对象子树模板：公开常用字段与事件、保留内部稳定 ID、实例明确显示改动位置。随后做模板更新传播和逐字段还原，再推广列表条目模板。

现有方案继承仍是整控件覆盖，应明确保持旧语义。迁移到细粒度覆盖属于独立版本变更，不能在打开面板时悄悄转换。

“节点外观预设”仍只复用外观；“控件模板”复用结构、功能和事件，两者不改成同一个概念。

## 8. 连线过渡的作者操作

这里的连线指编辑器中剧情／游戏模块间的执行连接，不是玩家剧情图控件里用于显示的线，也不含蓝图数据线。

默认连线保持简洁；配置后出现小标记，例如：

```text
车站结束 ── [淡黑 0.8 秒] ── 家中开始
```

点线或标记在右侧编辑“这次连接”的过渡方式、总时长及预览。详细设置可展开淡出／停留／淡入、颜色。选中仍只高亮，不增加端点圆圈、选中数量横条或浮动断开按钮。

首批效果：直接切换、叠化、经过颜色（黑／白为快捷选择）。之后再增加擦除、遮罩等，并复用相同的描述与预览入口。

区别两种情况：

- 未配置：不新增效果，继续沿用原演出／场景的既有衔接。
- 明确选择“直接切换”：本次衔接不使用可被本连接覆盖的自动视觉过渡。

因此旧工程未操作时表现不变；新建无其他过渡的普通连接自然是直接切换。

## 9. 不同连接的语义

| 连接 | 建议 |
| --- | --- |
| 剧情段落或选择分支 → 下一段 | 设置本次路径的画面过渡 |
| 启动演出／视频／独立页面的顺序衔接 | 在接入各自准备与关闭生命周期后支持 |
| 菜单按钮 → 新游戏／独立页面 | 设置归原按钮或蓝图导航，流程图是同一操作的视图 |
| 打开／关闭弹窗、HUD、提示层 | 使用该页面出现／消失动画，保持底层画面 |
| 读取存档 → 保存位置 | 保留系统恢复，最多设置恢复完成后的显示效果，不重跑场景入口 |
| 调用与返回 | 进入调用及返回后继续分开处理，不伪造固定返回目标 |
| 折叠剧情组、页面引用、复杂事件汇总 | 定位真实出口；聚合线不另存转场 |
| 蓝图数据线、玩家剧情图装饰线 | 不添加执行过渡 |

剧情组仍只有组织作用。同一组的多个出口可以各有过渡；打组、进入、解组都不能改变播放次数。

## 10. 存储身份与编辑规则

过渡属于真实源节点的稳定出口，例如一个具有稳定 ID 的选项，而不是绘图组件生成的边 ID。分组投影使用已有的 `storySource/storyPort/storyTarget` 映射。

- 同一目标可有不同入线效果。
- 改接目标保留源出口的本次设置；撤销恢复目标和设置。
- 无目标的出口可以保留非活动配置，须明确显示，避免隐藏生效。
- 删除出口一并删除本地过渡；复制节点重建出口身份并正确复制配置。
- 自动删除中间步骤并衔接两端时，两个设置不可无提示合并；优先保留存活源出口的设置，并把被删除的设置纳入同次撤销与操作说明。
- 复杂共享蓝图只提供定位入口，不复制或重写第二份导航。
- 文本模式需有可往返表示；无法表示的设置不能在切模式时静默丢失。

## 11. 一次可见画面衔接，只决议一次视觉过渡

建议以两次实际呈现之间的区间为单位，确定性地选择一次过渡：

1. 条件、参数赋值等不呈现画面的节点按原顺序执行；待处理的视觉请求继续传递。
2. 此区间存在多条显式连接设置时，以最后经过的显式设置为准；未设置不覆盖已有请求，显式直接切换会取消这次待处理效果。预览／诊断展示生效来源和被覆盖项。
3. 没有显式连接设置时，沿用原有演出／场景机制。
4. 必须在开始绘制过渡前完成同一边界的仲裁；不能先播旧演出淡出，再追加一次新连线淡出。已完成的另一次独立演出不倒退撤销。
5. 到首个可呈现或等待交互的边界消费请求。不能在黑幕下等待玩家选择，或无限等待“整个目标逻辑执行完”。

这项规则是推荐设计，实施前需在运行协调器里验证；不是给目前的全局 pending 变量再增加一次赋值。第一版不再另添目标模块默认／来源模块默认等多层优先级。

## 12. 运行时边界

当前 `jump.sceneTransition` 会令 `vn_current_scene = None`，重走入场动作、参数初始化和页面场景生命周期。普通段落只做视觉衔接不能借用这一步。应提取纯视觉描述，同时保留真实场景跳转自己的导航与参数语义。

游戏不能为了叠化同时运行两个剧情模块。应保留旧画面的显示结果，正常推进一条执行路径，准备目标首个画面后完成过渡。目标没有背景或角色变化时，叠化可能没有明显效果；模块不是自动清空舞台的独立视频片段。

现有 `vn_stage_transition` 只混合舞台层，不混合全部 UI。剧情舞台、独立页面替换、覆盖层动画可共享效果描述，但必须有各自的图层和生命周期适配。

默认音乐沿原播放规则继续；短视觉过渡不自动停止或重播 BGM。配音、文字计时和交互从目标显现并可操作的约定边界开始。音频交叉淡化作为后续独立选项，不塞入首版基础面板。

过渡期间同一次导航只执行一次，重复点击不重复运行按钮动作。跳过、取消、返回标题、读档与回滚需要清理或恢复表现状态，不重跑剧情副作用。

编辑器可提供样例效果预览；从真实模块预览衔接时必须使用实际运行上下文。动态条件、存档目标和随机结果不能通过静态缩略图假装已被准确模拟。

## 13. 覆盖层退出需补完整生命周期

目前关闭页面会立即移出打开列表，并释放该页动画和媒体。因此不能在“关闭后”事件里补一个退出动画。

目标顺序应为：

```text
请求关闭 → 校验允许关闭 → 停止接收新操作 → 播放退出 → 释放页面 → 返回结果一次
```

父页面强制关闭、读档和导航取消有明确的直接完成／清理路径，不留下等待者。页面自带出现／消失动画可以被不同调用入口复用；调用处有需要再作本次覆盖，来源明确。

复杂长过场包含镜头、配音、人物动作及剧情含义时，继续作为演出模块。未来时间轴过渡预设应有明确切换画面标记与完成边界，只控制表现，不承担导航或修改剧情参数。

## 14. 建议分期

1. **建立功能归属和统一描述。** 先重组文字、图片、点击及常用输入，保留旧数据和已完成的通用区／右键／作用域；补共同属性多选。
2. **做少量真正可组合的功能。** 从声音反馈、提示、文字效果、排列／裁切开始，完成依赖、启停、移除、撤销、引用和两端运行；独立解耦输入类型与来源。
3. **接入第一批真实剧情出口过渡。** 先解决纯视觉契约、仲裁和首个呈现边界，再加线标记、面板和预览。
4. **扩展页面衔接与复合模板。** 完成覆盖层关闭生命周期；实现按钮／设置行模板、公开字段、更新与覆盖，再逐步推广业务列表。

第一批完成标准：一次添加能力能在编辑、保存、预览、游戏、参数／蓝图和撤销上完整成立；一次连接过渡在分支、分组、改接、文本往返、跳过和读档下仍只按正确路径执行一次。

按用户约定，只有在具体实施范围全部完成后，才统一编译、验证与验收。当前仅保留本提案与对话内交互示意，没有启动产品变更。
