# 玩家剧情流程图：子剧情调用与返回

日期：2026-11-14。实现、统一构建及功能验收完成；单测临时目录清理有一项自动审批拒绝。

## 本次解决的问题

实际故事是“A 调用子剧情 X，X 返回后继续 B”，旧玩家图却把调用目标与后续画成 `A → X`、`A → B`，容易被理解为两个可选分支。现在外层按 `A →〔X〕→ B` 显示，真正的选项和条件分支仍然分叉。

- 子剧情卡保留剧情标题和原来的黑底、多字体／字号、颜色、字间距。右侧小箭头表示可以进入；双击或 Enter 查看正文，返回按钮逐层退出。
- 同一段 X 在两处被调用，外层有两张独立卡，各自接自己的后续；内部正文、文字设置和布局共用。
- 子剧情里可以再调用子剧情，也可以保留原有显示分组。递归引用回到已有浏览层，不无限新增页面。
- 若子剧情结束游戏、返回标题或没有可达返回路径，不虚构“返回后继续”的连线。真正的选择、条件、合流和独立入口保留。
- 跟随剧本／自定义、分支图／目录、作者控件和没有作者控件时的默认流程图页面都使用相同规则。

本次是玩家剧情图的显示和浏览改进。现有“调用子剧情”指令及实际执行的调用／返回顺序保持；没有要求作者重新建立两条剧情。

## 编辑、状态与重玩

编辑器中，单击调用卡查看详情，双击／Enter 进入；返回恢复原调用卡、滚动和缩放。内部图可以选节点、编辑位置，连线详情说明进入子剧情或返回后继续。切换内容来源、撤销重做、保存重开仍保留对应配置。

外层每次调用的位置独立保存；X 内部位置保存在 X 的共享视图，Y 内部位置属于 Y。旧根图坐标不自动搬进内部图，避免已有大坐标让内部内容出现在画布很远的位置。原有显示组仍使用原结构；新合成的调用卡不写入作者条目列表。

解锁按实际调用位置判断：走过第一处 X 不会解锁第二处 X 的入口。共享正文的已读状态共用，总进度按真实条目去重。当前节点同时参考真实调用链；从第一调用查看 X 时，不会把正在第二调用里播放的 X 误标为当前。

从内部节点重玩时，确认接受后才生成一次性的重玩请求。运行时按所浏览的调用路径建立 Ren’Py 原生调用帧，再进入目标节点，因此重玩 Y 能依次返回 X，再回到所选调用者自己的 B 或 C。取消确认、普通启动和读档会清除残留请求，普通节点重玩仍走原路径。

## 验收中发现并处理的情况

1. 新单测对 `nodeIds` 的顺序假设错误，改为集合等价；实际展示条目和连线的顺序断言保留。
2. 首次桌面夹具填入不合法的 `rows: 0`，尚未创建运行目录。移除该字段使用默认滚动；产品未变。
3. 桌面连线检查取中点，恰与另一线拐角重叠。改沿目标线选择实际命中的位置，再真实点击并断言目标被选中，没有 force 点击。
4. 原生测试器默认随机选择控件内点击位置，两次点击不满足真实双击的距离限制。测试改为相同位置；前置清理先退出标题子页，再按状态返回主菜单。产品双击规则未放宽。
5. 重玩实际原生返回要求完整引擎调用帧，仅替换 return stack 不足。最终使用原生 `Context.call` 建立配套帧，真实返回、回滚及本次存读档已验收。
6. 为调用卡添加字形箭头后，行为检查通过，但实际默认字体把符号画成缺字方框。最终改为原生绘制，并把文字断言换为真实几何和像素检查。字形版本的成功报告和缺字截图保留为历史证据，不视为最终视觉通过。

所有失败日志、报告、trace、截图、生成源码和夹具证据保留；没有通过修改产品行为来迁就测试器。
