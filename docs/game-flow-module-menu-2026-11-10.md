# 流程图直接添加模块

2026-11-10 实现与统一验收记录。主任务统一 build04（含类型检查）和76项相关单测通过；本功能的顶层流程桌面18组、剧情连线回归17组及页面路线8组均通过。这里只报告流程编辑器的验证，整轮其他工作进度见主交接文档。

## 新增与插入

- 顶层工具栏“添加模块”和空白处右键直接打开搜索菜单，按页面、动画演出、视频分组。选择已有资源即创建模块，支持搜索、方向键、Enter和Esc。
- 普通新增只创建未连接模块，不依据选中的线、节点或终点偷偷修改流程。空白右键使用鼠标位置对应的画布坐标；工具栏使用当前可见画布中心。普通新增不改变缩放和平移。
- 节点右键另保留明确的“在此出口插入…”。节点属性中的三个“插入”按钮也属于该操作。它已明确来源，不再显示插入位置下拉框；选资源后自动衔接原来的后续模块，并且一次撤销完整恢复。
- 原来 `A → B` 的过渡属于 A。显式插入 X 后，A 的过渡用于 `A → X`，X 的过渡保持未配置。普通新增不复制任何旧出口设置。
- 页面显示方式、等待、计时、取消以及蓝图输入仍在创建后的节点属性编辑。调用现有开场时间轴资源的能力保持；这里的动画演出清单与普通蓝图工作区的时间轴预设清单不是同一个入口。

## 无连接模块的归属

保留已有的两组节点库存和文件结构，不增加“待接线”字段。是否属于标题前或新游戏前，按实际的 `next` 连线是否连接入口或完成出口判断。标题按钮、读档、取消和返回标题的导航投影不参加该判断。

新模块暂存在有空位的库存中，但不执行，也不会因为库存位置而自动排在旧流程末尾。首次添加前固化旧工程推导出来的连线，确保原先没有显式连线的工程也保持原执行路线。

完全脱离入口和完成出口的一组模块可以先互相连线。接上某条流程的入口或完成出口后，该组全部节点原子归入相应库存；共同尾部的其他前驱也一并处理。标识、参数、名称、位置和按来源保存的过渡全部保留。

已连接标题入口或标题终点的组不能直接与新游戏合并，反之亦然。需要先断开与原流程的所有连接，再接入另一条。循环、同时连到两个生命周期，以及迁移后超过每组64个模块都在写入前拒绝；普通新增总上限为128个模块。数量限制包含未连接库存，并非只统计正在执行的路线。

相同连线不生成写入或空撤销，旧隐式连线也不会因同目标拖接被固化。已坏的图仍可断边修复。外部编辑形成“已连接但存错库存”的数据会明确诊断，不把它当成可正常执行的路线。

初次桌面验收和带只读事件日志的复验都发现：旧节点已选中时，普通新增模块虽然成功写入，却失去选中状态，右侧属性仍停留在旧节点。日志确认在 Enter 后、保存前已发生，视口和焦点恢复没有造成选择变化。原因是每次渲染新建的 `onSelectionChange` 回调让 React Flow 重放旧选择，在新节点进入画布状态前覆盖了请求的节点ID。

build04将该回调稳定化，并通过 ref 读取当前连线选择，保留原来的单选、多选和连线处理。没有增加延时、强制适应视口或额外选择状态机。第11组现在同时检查旧节点已选中时的鼠标与键盘新增：只选中新节点、旧节点取消选中、视口不动、线路不改，鼠标新增可单次撤销；键盘新增保留位置、撤销重做及手动接线检查。最终事件日志显示保存前后均保持新节点ID。
